The shell is a text prompt where you type commands, and it is the universal remote control for every server, container, and CI runner you will ever touch. This lesson covers moving around the filesystem, inspecting files, matching many files at once with wildcards, and wiring commands together with redirection — the handful of skills you reach for in every single terminal session.

Getting oriented

Beginner A shell (usually bash or zsh) reads what you type, runs it, and prints the result. The prompt ends in $ for a regular user or # for root. Three commands tell you where you are and what is around you:

pwd
# -> /home/ada/projects

ls
# -> README.md  src  tests

ls -la
# -> drwxr-xr-x  5 ada ada 4096 Oct  8 11:02 .
# -> drwxr-xr-x 24 ada ada 4096 Oct  8 10:55 ..
# -> -rw-r--r--  1 ada ada  182 Oct  8 11:02 .env
# -> -rw-r--r--  1 ada ada 1420 Oct  8 11:00 README.md

-l gives the long listing (permissions, owner, size, date); -a shows hidden dotfiles — files whose name starts with ., like .env and .gitignore.

Moving around the filesystem

CommandWhat it does
pwdPrint the working directory — “where am I?”
cd <dir>Change directory. cd .. up one, cd ~ home, cd - previous directory.
ls / ls -laList files; long form, including hidden files.
mkdir -p a/b/cMake directories; -p creates every missing parent.
cp src dst / cp -r dir dstCopy a file; -r to copy a directory tree.
mv old newMove or rename (same command for both).
rm file / rm -r dirRemove. No undo, no recycle bin.
touch fileCreate an empty file, or bump an existing file's timestamp.
 
cd ~/projects
mkdir -p demo/src/handlers
cd demo
pwd
# -> /home/ada/projects/demo

touch src/main.ts
cp src/main.ts src/main.bak.ts
mv src/main.bak.ts src/old-main.ts
ls src
# -> handlers  main.ts  old-main.ts

Absolute vs relative paths

An absolute path starts at root: /etc/hosts, /home/ada/projects. A relative path is measured from your current directory: src/main.ts, ./config (here), ../sibling (one level up). Absolute paths work from anywhere; relative paths are shorter but depend on pwd.

Viewing files

Beginner You rarely open an editor just to glance at a file. Four tools cover reading:

CommandUse it when
cat fileThe file is short — dump the whole thing to the screen.
less fileThe file is long — scroll with arrows/space, / to search, q to quit.
head -n 20 fileYou only want the first lines (default 10).
tail -n 20 fileYou only want the last lines (default 10).
tail -f fileFollow a growing file live — the standard way to watch a log.
 
head -n 3 /etc/passwd
# -> root:x:0:0:root:/root:/bin/bash
# -> daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
# -> bin:x:2:2:bin:/bin:/usr/sbin/nologin

tail -f /var/log/nginx/access.log
# -> ...new request lines appear as they arrive; Ctrl-C to stop
tail -f is how you watch an app serve traffic in real time. Combine it with a filter: tail -f app.log | grep ERROR shows only error lines as they appear.

Wildcards and globbing

Beginner The shell expands glob patterns into a list of matching filenames before the command runs — the command never sees the *, only the files it matched.

PatternMatches
*Any run of characters: *.log → every file ending in .log.
?Exactly one character: report?.csv → report1.csv, reportA.csv.
[abc]One character from a set: img[12].png → img1.png, img2.png.
{a,b}Brace expansion (not a glob — it expands even with no files): cp f.{yml,yaml} bak/.
**Recursive, when globstar is enabled: ls **/*.ts.
 
ls *.yaml
# -> compose.yaml  config.yaml

cp config.{yml,yaml} backup/       # brace expansion -> two files
shopt -s globstar                  # enable ** in bash
ls **/*.ts
# -> src/main.ts  src/handlers/user.ts  tests/main.test.ts

echo *.none
# -> *.none      (no match: bash leaves the literal pattern)
Common mistakes: (1) rm * with a stray space, like rm * .bak, deletes everything in the directory and then complains it cannot find .bak. (2) A glob that matches nothing is passed through literally in bash, so rm *.tmp in a directory with no .tmp files errors on a file literally named *.tmp. Preview a destructive glob with ls or echo first: echo rm *.tmp.

Redirection and pipes

Intermediate Every command has three streams: stdin (0, input), stdout (1, normal output), and stderr (2, errors). Redirection points those streams at files; a pipe points one command's stdout at the next command's stdin.

OperatorEffect
> fileSend stdout to file, overwriting it.
>> fileSend stdout to file, appending.
2> fileSend stderr to file.
2>&1Merge stderr into wherever stdout currently points.
< fileFeed file into the command as stdin.
cmd1 | cmd2Pipe cmd1's stdout into cmd2's stdin.
 
# Capture everything (output AND errors) into one log
./build.sh > build.log 2>&1

# Append a timestamped line to a running record
echo "deploy started $(date -Iseconds)" >> deploy.log

# Throw away noise you do not care about
find / -name "*.conf" 2>/dev/null         # discard permission-denied errors

# Pipes: chain small tools into an answer
cat access.log | grep " 500 " | wc -l
# -> 42

ps aux | grep -v grep | grep node
# -> ada  3120  0.4  1.2  node server.js

Order matters: > file 2>&1 sends both streams to the file, but 2>&1 > file sends stderr to the old stdout (the terminal) first, then redirects only stdout — a classic mistake. Put 2>&1 after the >.

Exercises

  • Create demo/ with mkdir -p demo/a/b, cd into it, and get back to your previous directory with a single cd -.
  • Make three files touch note{1,2,3}.txt, then list only the ones ending in an odd digit using a glob.
  • Run a command that prints to both stdout and stderr (e.g. ls /etc /nope) and capture only the errors to errs.txt.
  • Count how many lines in /etc/passwd use the /bin/bash shell with a single grep | wc -l pipe.

Mini-project: a one-line log triage

Given an application log, produce a ranked count of the HTTP status codes it recorded, highest first — without opening an editor. Assume lines look like ... "GET /api" 200 ....

# Extract the status code (field 9 here), count each, sort by frequency
cat access.log | awk '{print $9}' | sort | uniq -c | sort -rn | head
# -> 2041 200
# ->  318 404
# ->   42 500
# ->   11 502

Then save the summary and append a header for a daily report: { echo "=== $(date +%F) ==="; cat access.log | awk '{print $9}' | sort | uniq -c | sort -rn; } >> status-report.txt. You have just built a reusable pipeline out of five tools that each do one thing well — the essence of the shell.
