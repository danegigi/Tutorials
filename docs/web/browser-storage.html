The browser offers several ways to persist data on the client. Each has different size limits, APIs, and lifetimes. Choosing the right one — and knowing what not to store — is the whole lesson.

The options at a glance

localStorage & sessionStorage

Beginner Simple key→string stores. Serialize objects with JSON yourself.

// Store
localStorage.setItem("theme", "dark");
localStorage.setItem("prefs", JSON.stringify({ fontSize: 16 }));

// Read (returns null if absent)
const theme = localStorage.getItem("theme");
const prefs = JSON.parse(localStorage.getItem("prefs") || "{}");

localStorage.removeItem("theme");
localStorage.clear();

// React to changes from OTHER tabs
window.addEventListener("storage", (e) => {
  if (e.key === "theme") applyTheme(e.newValue);
});
Common mistakes: (1) storing non-strings — setItem("x", {a:1}) saves the string "[object Object]". Always JSON.stringify. (2) Assuming it's always available — it throws in private mode on some browsers and when quota is exceeded, so wrap writes in try/catch. (3) It's synchronous and blocks the main thread; don't put megabytes in it.

This very PWA uses localStorage for your theme choice, completed lessons, and bookmarks — all small, all per-device.

Cookies

Intermediate Cookies are automatically sent to the server on every request to their domain — which is why they're used for sessions, and why they need security flags:

// Server sets them (not JS) for auth:
Set-Cookie: session=abc; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=3600
HttpOnly cookies cannot be read by JavaScript — this is the point: it protects session tokens from XSS theft. Store auth tokens in HttpOnly cookies set by the server, not in localStorage, which any injected script can read.

IndexedDB

Intermediate A real transactional, indexed, asynchronous database in the browser — the right tool for offline-first apps storing lots of structured records. The raw API is verbose; most apps wrap it with a tiny library like idb.

const db = await openDB();   // promisified wrapper
await db.put("todos", { id: 1, text: "Buy milk", done: false });
const todo = await db.get("todos", 1);
const all = await db.getAll("todos");
await db.delete("todos", 1);

Cache API

Stores whole Request/Response pairs — the storage layer service workers use to make pages work offline (covered in the Service Workers lesson):

const cache = await caches.open("v1");
await cache.add("/styles.css");            // fetch + store
const hit = await cache.match("/styles.css");  // serve from cache

Checking your quota

const { usage, quota } = await navigator.storage.estimate();
console.log(`${(usage/1e6).toFixed(1)} MB of ${(quota/1e6).toFixed(0)} MB used`);
// Ask the browser not to evict your data under pressure:
await navigator.storage.persist();

Exercises

  • Persist a theme toggle in localStorage and sync it across two tabs with the storage event.
  • Wrap a localStorage write in try/catch and handle the quota-exceeded / private-mode case.
  • Store a list of todos in IndexedDB (via idb) and read them all back.

Mini-project: an offline notes app

Build a notes app that saves each note to IndexedDB (so it survives reloads and works offline), keeps the UI theme and sort order in localStorage, and shows a storage-usage meter via navigator.storage.estimate(). Deliberately keep any auth token out of localStorage and note why.
