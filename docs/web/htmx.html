HTMX lets you build dynamic, interactive UIs by adding attributes to HTML — the server returns HTML fragments, and HTMX swaps them into the page. No JSON API, no client-side framework, no build step. It's the "hypermedia" approach to interactivity.

Setup

<script src="https://unpkg.com/htmx.org@2.0.3"></script>
<!-- or vendor it locally for offline/production -->

The core idea

Beginner An element declares what request to make, when, and where to put the response. The server replies with an HTML fragment, which HTMX swaps into the DOM.

<button hx-get="/clicked" hx-target="#result" hx-swap="innerHTML">
  Click me
</button>
<div id="result"></div>

<!-- Server responds to GET /clicked with:  -->
<p>You clicked at 14:32</p>
<!-- …which replaces the contents of #result -->
AttributeMeaning
hx-get/post/put/patch/deleteIssue that HTTP request to the URL.
hx-triggerWhat fires it: click (default for buttons), keyup changed delay:300ms, load, revealed, every 2s.
hx-targetCSS selector for where the response goes (default: the element itself).
hx-swapHow to insert: innerHTML (default), outerHTML, beforeend, delete.

Live search (the canonical example)

<input type="search" name="q"
       hx-get="/search"
       hx-trigger="input changed delay:300ms, search"
       hx-target="#results"
       hx-indicator="#spinner">
<span id="spinner" class="htmx-indicator">Searching…</span>
<ul id="results"></ul>

<!-- Server returns just the <li> rows for the query -->

The name="q" value is sent automatically as a query param. delay:300ms debounces; hx-indicator shows a loading element while the request is in flight.

Forms and swapping yourself out

<form hx-post="/todos" hx-target="#list" hx-swap="beforeend"
      hx-on::after-request="this.reset()">
  <input name="text" required>
  <button>Add</button>
</form>
<ul id="list"></ul>

<!-- Delete a row, removing itself from the DOM -->
<li>
  Buy milk
  <button hx-delete="/todos/42" hx-target="closest li" hx-swap="outerHTML swap:200ms">✕</button>
</li>

Out-of-band swaps

Intermediate One response can update several parts of the page — the targeted element plus any fragment marked hx-swap-oob:

<!-- Response to POST /cart/add -->
<div id="added-row">Added to cart</div>
<span id="cart-count" hx-swap-oob="true">3</span>   <!-- updates the header badge too -->

Why HTMX

HTMX shines when your backend already renders HTML (Go templates, templ, Rails, Django, PHP). You keep rendering on the server, send fragments, and get SPA-like interactivity without a JSON API or a JS framework. It's less suited to highly client-stateful apps (rich offline editors, canvas tools) where state genuinely lives in the browser.
Common mistakes: (1) returning a full HTML page from an HTMX endpoint — return only the fragment to swap. (2) forgetting that swapped-in content needs its own HTMX attributes to be interactive (they are processed automatically on swap, but inline <script> in a fragment won't re-run unless you account for it). (3) using HTMX for client-only interactions (toggling a class) where plain CSS/JS is simpler.

Exercises

  • Build a counter button that GETs /inc and swaps the new count into a <span>.
  • Add a debounced live-search input returning <li> rows with a loading indicator.
  • Add a delete button that removes its own row with an outerHTML swap and a fade transition.

Mini-project: an HTMX todo list

Pair HTMX with a small server (the Go or Bun HTTP lesson gives you one): POST /todos appends a rendered <li>, DELETE /todos/:id removes a row, and a cart-style count updates out-of-band. The whole UI is server-rendered HTML with zero custom JavaScript — the hypermedia model end to end.
