React is a library for building UIs out of small, reusable components that describe what the screen should look like for a given state. You write a function that returns markup, React renders it, and whenever your data changes React re-renders and updates the DOM for you.

Scaffolding a project

Beginner The fastest way to a working React app is Vite. It gives you a dev server with hot reloading and a production build with no config:

npm create vite@latest my-app -- --template react
cd my-app
npm install
npm run dev
# expected output
  VITE v5.4.0  ready in 320 ms

  ➜  Local:   http://localhost:5173/
  ➜  press h + enter to show help

Open that URL and edit src/App.jsx — the page updates instantly without a reload. The entry point wires your root component into the page:

// src/main.jsx
import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(<App />);
The -- before --template react is required: it tells npm to pass the flag to create-vite rather than consume it itself. Use react-ts instead of react for a TypeScript project.

What JSX is

JSX is HTML-like syntax inside JavaScript. It is not run by the browser — a build step compiles each tag into a React.createElement call that returns a plain object describing the UI:

const el = <h1 className="title">Hello</h1>;
// compiles to:
const el = React.createElement("h1", { className: "title" }, "Hello");

Because it compiles to JavaScript, three rules follow:

  • Attributes use JS names. It's className (not class) and htmlFor (not for), because class is a reserved word.
  • {expression} embeds JavaScript. Anything in braces is evaluated and inserted.
  • One root element. A component returns a single node; wrap siblings in a fragment <>...</> to avoid an extra wrapper div.
function Greeting() {
  const name = "Ada";
  const hour = new Date().getHours();
  return (
    <>
      <h2 className="greeting">Hello, {name}</h2>
      <p>{hour < 12 ? "Good morning" : "Good afternoon"}</p>
    </>
  );
}
Braces embed expressions, not statements. {if (x) ...} is a syntax error — use a ternary {x ? a : b} or {x && a} for conditional rendering, and compute anything complex in a variable before the return.

Components and composition

A component is a function whose name starts with a capital letter and returns JSX. You build screens by composing small components:

function Avatar() {
  return <img className="avatar" src="/me.png" alt="" />;
}

function Card() {
  return (
    <div className="card">
      <Avatar />
      <p>Composed from smaller pieces.</p>
    </div>
  );
}
Capitalization matters: <Avatar /> renders your component, but <avatar /> is treated as an unknown HTML tag. Always capitalize component names.

Props

Props pass data from a parent to a child. They are a read-only argument object — a child must never reassign them. The special children prop holds whatever JSX you nest inside the tag:

function Button({ label, onClick, variant = "primary" }) {
  return (
    <button className={`btn ${variant}`} onClick={onClick}>
      {label}
    </button>
  );
}

function Panel({ title, children }) {
  return (
    <section className="panel">
      <h3>{title}</h3>
      {children}
    </section>
  );
}

// usage
<Panel title="Settings">
  <Button label="Save" onClick={save} />
</Panel>
Destructure props in the parameter list ({ label, onClick }) and give defaults there (variant = "primary"). It documents a component's API at a glance.

State with useState

Beginner Props come from the parent; state is data a component owns and can change over time. useState returns the current value and a setter. Calling the setter asks React to re-render with the new value:

import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);   // 0 is the initial value
  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}

State is a snapshot. Within one render, count is a fixed value — the setter does not change it immediately. So this only increments by one:

setCount(count + 1);
setCount(count + 1);   // both read the SAME snapshot of count → +1 total

When the next value depends on the previous one, pass a functional update. React feeds each call the latest value:

setCount(c => c + 1);
setCount(c => c + 1);   // now +2 total

Rendering lists

Render an array with .map, returning one element per item. Each element needs a stable key so React can match items across renders:

function TodoList({ todos }) {
  return (
    <ul>
      {todos.map(todo => (
        <li key={todo.id}>{todo.text}</li>
      ))}
    </ul>
  );
}
The key rule: a key must be stable, unique, and tied to the item's identity — use a database id, not the array index. Using the index as the key breaks when the list is reordered, filtered, or has items removed: React reuses the wrong DOM node and inputs show up attached to the wrong row.

Events and controlled inputs

Attach handlers with camelCase props like onClick and onChange — pass the function, don't call it:

<button onClick={handleSave}>Save</button>    {/* right: pass it */}
<button onClick={handleSave()}>Save</button>  {/* wrong: runs on render */}

A controlled input gets its value from state and writes back through the setter, making React the single source of truth for the field:

function NameField() {
  const [name, setName] = useState("");
  return (
    <input
      value={name}
      onChange={(e) => setName(e.target.value)}
      placeholder="Your name"
    />
  );
}

Effects with useEffect

Intermediate Most logic belongs in event handlers. useEffect is for synchronizing with something outside React — a network request, a subscription, a timer. It runs after the render is painted:

import { useEffect, useState } from "react";

function Clock() {
  const [now, setNow] = useState(new Date());

  useEffect(() => {
    const id = setInterval(() => setNow(new Date()), 1000);
    return () => clearInterval(id);   // cleanup: runs before re-run and on unmount
  }, []);   // [] → run once after the first render

  return <p>{now.toLocaleTimeString()}</p>;
}

The dependency array controls when the effect re-runs:

DepsWhen the effect runs
[]Once, after the first render
[userId]After the first render and whenever userId changes
omittedAfter every render (rarely what you want)
 
useEffect(() => {
  let active = true;
  fetch(`/api/users/${userId}`)
    .then(r => r.json())
    .then(data => { if (active) setUser(data); });
  return () => { active = false; };   // ignore a stale response
}, [userId]);

Lifting state up

When two components need the same data, move the state to their nearest common parent and pass it down as props. The parent owns the state; children receive the value and a callback to change it:

function Parent() {
  const [query, setQuery] = useState("");
  return (
    <>
      <SearchBox query={query} onChange={setQuery} />
      <Results query={query} />
    </>
  );
}

Now the search box and the results list stay in sync because they read from one shared source instead of each keeping a private copy.

Common mistakes

  • Mutating state directly. todos.push(x) then setTodos(todos) does nothing — React compares the same array reference and skips the re-render. Create a new value: setTodos([...todos, x]).
  • Index as key (or missing/duplicate keys). Breaks on reorder/removal and triggers a console warning. Use a stable id.
  • Stale closures. An effect or handler captures the state value from the render it was created in. Use a functional update setCount(c => c + 1) or add the value to the dependency array.
  • Missing effect dependencies. Leaving out a value the effect uses causes it to work with stale data. List every reactive value it reads; the react-hooks/exhaustive-deps lint rule catches this.
  • Calling hooks conditionally. Hooks must run in the same order every render — never inside an if, loop, or after an early return. Call them at the top level of the component.

Exercises

  • Scaffold a Vite React app and change the counter so two rapid clicks reliably add two, using a functional update.
  • Render a list of five items with correct keys, then add a "remove" button — confirm no key warning appears in the console.
  • Build a controlled text input that shows a live character count below it.
  • Write a component that fetches /api/users/:id in a useEffect keyed on id, with cleanup that ignores a stale response.
  • Lift state up: give two sibling components a shared counter owned by their parent.

Mini-project: a controlled todo list

Build a todo app in a single Vite React project. Keep an array of { id, text, done } objects in useState on a parent component, plus a filter state of "all" | "active" | "done".

  • Add: a controlled input whose submit handler appends { id: crypto.randomUUID(), text, done: false } with a fresh array (never push), then clears the field.
  • Toggle: clicking an item flips its done by mapping to a new array and replacing only the matching item.
  • Remove: a delete button filters the item out by id.
  • Filter: three buttons set the filter; the rendered list is todos.filter(...) derived from state, not a second copy stored in state.
  • Use each todo's id as its key, and show a live count of remaining active items.

This exercises every concept in the lesson at once: components and props, immutable state updates, lists with keys, controlled inputs, event handlers, and deriving the visible list from a single source of truth.
