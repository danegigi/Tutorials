Vue is a progressive framework: you can drop it into one page with a single <script> tag, or scaffold a full build-tooled single-page app — and the mental model is the same either way. You describe what the UI should look like for a given piece of state, and Vue keeps the DOM in sync as that state changes. This lesson uses Vue 3 with the Composition API and <script setup>, the current recommended style.

Two ways to start an app

1. CDN + createApp (zero build)

Beginner The fastest way to try Vue is a plain HTML file — no Node, no install. Great for a prototype, a demo, or sprinkling interactivity onto an existing page.

<!DOCTYPE html>
<div id="app">
  <button @click="count++">Clicked {{ count }} times</button>
</div>

<script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
<script>
  const { createApp, ref } = Vue;
  createApp({
    setup() {
      const count = ref(0);
      return { count };   // anything returned here is usable in the template
    }
  }).mount('#app');
</script>

Open the file in a browser and the button works. createApp(...) builds the app instance; .mount('#app') tells Vue which existing element to take over.

2. npm create vue@latest (Vite build)

Beginner For anything real you want a build step: single-file components (.vue), hot-reload, and a bundler. The official scaffolder sets this up:

$ npm create vue@latest

Reactive state: ref() and reactive()

Beginner Reactivity is Vue's core trick: wrap a value so that when it changes, every part of the UI using it updates automatically. There are two tools.

ref() — for any single value

import { ref } from 'vue';

const count = ref(0);
const name  = ref('Ada');

// In JavaScript you must use .value to read or write:
count.value++;          // now 1
console.log(name.value); // 'Ada'

ref() wraps the value in an object with a .value property. That indirection is what lets Vue track reads and writes.

reactive() — for objects

import { reactive } from 'vue';

const state = reactive({ count: 0, user: { name: 'Ada' } });

state.count++;              // no .value — reactive() returns a proxy
state.user.name = 'Grace';  // deeply reactive
The .value gotcha. In script you must write count.value; forgetting it is the single most common beginner bug (count++ on a ref increments the object, not the number, and does nothing useful). In the template, Vue unwraps refs for you — you write {{ count }}, not {{ count.value }}. So the rule is: .value in JS, no .value in the template.

Which to use? Reach for ref() by default — it works for primitives and objects alike and the explicit .value makes reactivity obvious. Use reactive() when you have a group of related fields you always touch together.

Derived state with computed()

Beginner A computed is a value calculated from other reactive state. It caches its result and only recalculates when a dependency changes — don't do this work in a plain function called from the template.

import { ref, computed } from 'vue';

const items = ref([
  { text: 'Learn Vue',  done: true  },
  { text: 'Build an app', done: false },
]);

const remaining = computed(() => items.value.filter(i => !i.done).length);
// remaining.value is 1, and updates automatically when any item's `done` flips.

Template syntax

Text interpolation

<p>Hello, {{ name }}! You have {{ remaining }} tasks left.</p>
<p>Total: {{ price * quantity }}</p>   <!-- any JS expression works -->

v-bind — bind an attribute

<a v-bind:href="url">link</a>
<a :href="url">link</a>                    <!-- : is the shorthand -->
<img :src="avatar" :alt="name">
<button :disabled="isLoading">Save</button>
<div :class="{ active: isOpen, done: task.done }"></div>  <!-- conditional classes -->

v-on — listen to events

<button v-on:click="count++">+1</button>
<button @click="addTodo">Add</button>              <!-- @ is the shorthand -->
<form @submit.prevent="save">...</form>            <!-- .prevent = preventDefault() -->
<input @keyup.enter="addTodo">                     <!-- key modifier -->

v-model — two-way binding

Beginner v-model wires a form input to a ref in both directions: type in the box, the ref updates; change the ref, the box updates.

<input v-model="newTodo" placeholder="What needs doing?">
<p>You typed: {{ newTodo }}</p>

<!-- works on checkboxes, radios, selects, textareas too -->
<input type="checkbox" v-model="showDone">
<select v-model="filter">
  <option value="all">All</option>
  <option value="active">Active</option>
</select>

Conditional & list rendering

v-if vs v-show

<p v-if="remaining === 0">All done! 🎉</p>
<p v-else-if="remaining === 1">One task left.</p>
<p v-else>{{ remaining }} tasks left.</p>

<div v-show="isOpen">Toggled with CSS display</div>
v-ifv-show
How it hidesRemoves the element from the DOMSets display: none
Toggle costHigher (create/destroy)Cheap (just CSS)
Use whenRarely toggled / may never renderToggled often

v-for with :key

<ul>
  <li v-for="todo in todos" :key="todo.id">
    {{ todo.text }}
  </li>
</ul>

<!-- with index -->
<li v-for="(todo, i) in todos" :key="todo.id">{{ i + 1 }}. {{ todo.text }}</li>
Always give v-for a :key — a stable, unique id per item (todo.id, not the array index). The key tells Vue which DOM node maps to which item so it can reuse nodes correctly when the list reorders. Using the index as the key, or omitting it, causes subtle bugs: checkbox state attaching to the wrong row after a sort or delete.

Components

Intermediate Components let you split a UI into reusable, self-contained pieces. With the Vite scaffold each lives in a .vue file with three blocks:

<!-- TodoItem.vue -->
<script setup>
const props = defineProps({
  todo: { type: Object, required: true }
});
const emit = defineEmits(['toggle', 'remove']);
</script>

<template>
  <li :class="{ done: todo.done }">
    <input type="checkbox" :checked="todo.done" @change="emit('toggle', todo.id)">
    <span>{{ todo.text }}</span>
    <button @click="emit('remove', todo.id)">✕</button>
  </li>
</template>

<style scoped>
.done span { text-decoration: line-through; opacity: 0.5; }
</style>

Props down, events up

Data flows down via props; a child asks its parent to change something by emitting an event up. The parent decides what to do:

<!-- App.vue (parent) -->
<script setup>
import { ref } from 'vue';
import TodoItem from './TodoItem.vue';

const todos = ref([
  { id: 1, text: 'Learn components', done: false },
]);

function toggle(id) {
  const t = todos.value.find(t => t.id === id);
  if (t) t.done = !t.done;
}
function remove(id) {
  todos.value = todos.value.filter(t => t.id !== id);
}
</script>

<template>
  <ul>
    <TodoItem
      v-for="todo in todos"
      :key="todo.id"
      :todo="todo"
      @toggle="toggle"
      @remove="remove"
    />
  </ul>
</template>

defineProps and defineEmits are compiler macros — available inside <script setup> without importing them.

Slots

Slots let a parent pass markup into a child, so a component can wrap arbitrary content:

<!-- Card.vue -->
<template>
  <div class="card">
    <slot>Default content if none provided</slot>
  </div>
</template>

<!-- usage -->
<Card><h3>Anything I want here</h3></Card>

Putting it together: a reactive todo list

This single-file component ties together refs, computed, v-model, v-for, v-if, and events — add, toggle, and remove:

<script setup>
import { ref, computed } from 'vue';

const todos   = ref([]);
const newTodo = ref('');
let nextId    = 1;

const remaining = computed(() => todos.value.filter(t => !t.done).length);

function addTodo() {
  const text = newTodo.value.trim();
  if (!text) return;                 // ignore empty submits
  todos.value.push({ id: nextId++, text, done: false });
  newTodo.value = '';                // clear the input
}
function toggle(id) {
  const t = todos.value.find(t => t.id === id);
  if (t) t.done = !t.done;
}
function remove(id) {
  todos.value = todos.value.filter(t => t.id !== id);
}
</script>

<template>
  <h2>Todos ({{ remaining }} left)</h2>
  <form @submit.prevent="addTodo">
    <input v-model="newTodo" placeholder="Add a task">
    <button>Add</button>
  </form>

  <p v-if="todos.length === 0">Nothing yet — add your first task.</p>
  <ul v-else>
    <li v-for="todo in todos" :key="todo.id" :class="{ done: todo.done }">
      <input type="checkbox" :checked="todo.done" @change="toggle(todo.id)">
      {{ todo.text }}
      <button @click="remove(todo.id)">✕</button>
    </li>
  </ul>
</template>

Common mistakes

  • Forgetting .value on a ref in script. count++ where count is a ref does nothing useful — you need count.value++. (In the template Vue unwraps it, so no .value there.)
  • Destructuring a reactive() object. const { count } = reactive({ count: 0 }) gives you a plain, non-reactive number — the connection to the proxy is lost. Keep the object and access state.count, or use toRefs() if you must destructure.
  • Missing or index-based :key on v-for. Always key by a stable unique id. Index keys break when the list reorders or items are removed.
  • Mutating props in a child. Props are one-way (read-only). Writing props.todo.done = true in a child is an anti-pattern; emit an event and let the owner change the data instead.
  • Doing heavy work in template expressions. Filtering/sorting inline in {{ }} re-runs on every render — use a computed so it caches.

Exercises

  • Build the CDN counter from the top of this lesson, then add a second button that resets the count to zero.
  • Add a filter to the todo list (All / Active / Done) using a <select v-model> and a computed that returns the visible todos.
  • Extract the list row into a TodoItem.vue component that takes a todo prop and emits toggle and remove.
  • Trigger the .value bug on purpose: write count++ (no .value) and observe nothing happens, then fix it — so you recognize the symptom.
  • Persist the todos to localStorage so they survive a page reload (write on change, seed the ref on load).

Mini-project: a notes app

Build a small notes app with the Vite scaffold. A NoteList renders a v-for of NoteCard components (each with a note prop and edit/delete emits); an input bound with v-model adds new notes; a computed shows a live count and a search box filters the list; and notes persist to localStorage. It exercises every concept here — refs, computed, template directives, props-down/events-up, and slots (give NoteCard a slot for optional footer actions) — in one coherent build.
