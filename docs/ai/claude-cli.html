Anthropic ships two CLI tools: Claude Code, an agentic coding agent that reads your codebase, edits files, and runs commands (comparable to Codex CLI and Kiro CLI), and ant, a lower-level CLI that puts the entire Claude API in your terminal for scripting. This lesson covers both — install, interactive mode, headless/CI, hooks, MCP, CLAUDE.md, and the ant API commands — basic through advanced.

Two tools, two purposes

Beginner

ToolWhat it isUse when
Claude Code (claude)Agentic coding agent — reads files, edits, runs commands, integrates with Git/MCP/hooksWriting code, refactoring, debugging, PR review
ant (ant)API-level CLI — every Claude API endpoint as a subcommandScripting, batch processing, CI/CD, raw API calls

Most developers use Claude Code day-to-day and reach for ant when they need to script the API (batch embeddings, classify documents, generate content at scale).

Installing Claude Code

Beginner

# macOS / Linux / WSL (native installer — recommended)
curl -fsSL https://claude.ai/install.sh | bash

# Homebrew (stable channel)
brew install --cask claude-code

# Homebrew (latest channel — gets new versions immediately)
brew install --cask claude-code@latest

# Verify installation
claude --version
# claude-code 1.x.x

On first run, Claude Code prompts you to log in with your Claude subscription or Anthropic Console account. You can also set an API key:

# Option 1: interactive login (prompts on first use)
cd my-project
claude

# Option 2: API key from environment
export ANTHROPIC_API_KEY=sk-ant-...
claude --version   # uses the key, skips login prompt

# Option 3: key from a secret manager (piped on stdin, never in env)
op read op://vault/anthropic/api-key | claude --api-key-stdin

Claude Code: interactive mode

Beginner Start Claude Code inside a project directory:

$ cd my-project
$ claude

╭──────────────────────────────────────────────╮
│  Claude Code                    [model: opus]  │
╜──────────────────────────────────────────────╯

> Add input validation to the user registration endpoint

# Claude reads the relevant files, proposes edits, asks for approval
# on each file change, and runs tests after editing.

You type in natural language. Claude Code reads your codebase, proposes changes, and asks for approval before writing. Key interactive commands:

CommandWhat it does
/helpShow all available commands and shortcuts
/modelSwitch model (Opus, Sonnet, Haiku)
/costShow token usage and cost for this session
/clearClear conversation context (start fresh)
/compactCompress context to fit more (preserves key info)
/reviewReview uncommitted changes or a PR
/initGenerate a CLAUDE.md file for the project
/mcpManage MCP servers
/hooksView and configure hooks
EscInterrupt the current generation
Ctrl+CCancel / exit

Claude Code: headless and CI mode

Intermediate For automation, CI/CD pipelines, and scripts, Claude Code runs non-interactively:

# Headless: one-shot, no interactive session
claude -p "Review the diff in src/ for security issues" --output-format json

# Headless with a specific model
claude -p "Write tests for src/handler.go" --model claude-sonnet-4-5

# Pipe input on stdin
echo "Fix the typo in this file" | claude -p

# Run in a CI pipeline (GitHub Actions)
- name: AI Code Review
  run: |
    claude -p "Review the PR changes for bugs and security issues. \
    Output a markdown review with severity ratings." \
    --output-format text \
    --max-turns 10

Key headless flags:

FlagWhat it does
-p / --printHeadless mode: run once, print output, exit
--output-format jsonOutput as JSON (parseable in scripts)
--output-format textPlain text output
--max-turns NLimit agent turns (safety in CI)
--model NAMESpecify the model
--allowedTools "Edit,Bash"Restrict which tools the agent can use
--permission-mode planPlan-only mode (no edits, just analysis)
 
# CI: plan-only review (read-only, no file edits)
claude -p "Analyze the auth middleware for vulnerabilities" \
  --permission-mode plan \
  --output-format json \
  --max-turns 5

# CI: full autonomous fix (dangerous — restrict tools carefully)
claude -p "Fix the failing test in src/handler_test.go" \
  --allowedTools "Edit,Read,Bash" \
  --max-turns 15 \
  --output-format text
In CI, always set --max-turns to limit runaway agent loops, and restrict --allowedTools to only what the task needs. An unrestricted agent in CI can make unlimited API calls and edit unexpected files.

CLAUDE.md: persistent instructions

Beginner Claude Code reads CLAUDE.md files (same role as AGENTS.md in other tools) for project-specific instructions. It looks for them in the project root and parent directories:

# CLAUDE.md — project instructions for Claude Code

## Project overview
This is a Go API server using Gin. The database is PostgreSQL with sqlc for queries.

## Commands
- Build: `go build ./cmd/server`
- Test: `go test ./...`
- Lint: `golangci-lint run`

## Conventions
- Use sqlc for all database queries — never raw SQL in handlers
- All handlers take `*gin.Context` and return JSON
- Error responses: {"error": "message", "code": "ERROR_CODE"}
- Log with slog, not fmt.Printf

## Don't
- Don't add new dependencies without checking with me first
- Don't modify migrations that have been deployed

Generate a starting point with /init, then refine it. The file is loaded into context on every session start.

CLAUDE.md hierarchy

Claude Code reads CLAUDE.md files from multiple levels, with closer files taking precedence:

~/.claude/CLAUDE.md          # global: your personal preferences (all projects)
project-root/CLAUDE.md        # project: conventions, commands, architecture
project-root/src/CLAUDE.md     # subdirectory: module-specific rules

Hooks: automated actions

Advanced Hooks let you run custom scripts automatically at specific points in Claude Code's workflow — without modifying Claude's behavior manually each time:

# .claude/settings.json — hook configuration
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{
          "type": "command",
          "command": ".claude/hooks/pre-edit-check.sh"
        }]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{
          "type": "command",
          "command": ".claude/hooks/format-after-edit.sh"
        }]
      }
    ]
  }
}

Common hook patterns:

Hook eventWhen it firesUse case
PreToolUseBefore a tool runs (Edit, Bash, etc.)Validate inputs, block dangerous commands, lint before writing
PostToolUseAfter a tool runsAuto-format, run tests, update docs
NotificationWhen Claude sends a notificationDesktop alerts, Slack pings
StopWhen Claude finishes a responseRun validation, update task tracking
 
#!/bin/bash
# .claude/hooks/format-after-edit.sh — auto-format Go files after edits
FILE="$1"  # the file that was edited
if [[ "$FILE" == *.go ]]; then
  gofmt -w "$FILE"
  golangci-lint run --fix "$FILE" 2>/dev/null || true
fi

MCP integration

Intermediate Claude Code connects to MCP servers for external tools:

# Add an MCP server (project-level: .mcp.json)
claude mcp add my-db -- npx -y @modelcontextprotocol/server-postgres "postgresql://localhost/mydb"

# List configured MCP servers
claude mcp list

# Remove a server
claude mcp remove my-db

# View server details
claude mcp get my-db

Once connected, Claude Code discovers the server's tools and can call them during a session — no code changes needed. See the MCP Servers Deep Dive lesson for building your own.

The ant CLI: scripting the Claude API

Intermediate ant is the official CLI for the Claude Platform API. It exposes every API endpoint as a subcommand, making it ideal for scripts, batch jobs, and CI/CD:

# Install ant
brew install anthropics/tap/ant
# or with Go:
go install 'github.com/anthropics/anthropic-cli/v2/cmd/ant@latest'

# Authenticate
ant auth login          # interactive login
# or: export ANTHROPIC_API_KEY=sk-ant-...

# List available models
ant models list
# claude-opus-5-5
# claude-sonnet-4-5
# claude-haiku-4-5

# Send a message
ant messages create \
  --max-tokens 1024 \
  --model claude-sonnet-4-5 \
  --message '{role: user, content: "Write a Go HTTP handler for health checks"}'

# Using YAML for complex messages (more readable than JSON)
ant messages create \
  --max-tokens 2048 \
  --model claude-sonnet-4-5 \
  --message-file message.yaml

Batch processing with ant

# Classify a batch of documents
for file in docs/*.md; do
  ant messages create \
    --max-tokens 100 \
    --model claude-haiku-4-5 \
    --message "{
      role: user,
      content: 'Classify this document as tutorial, reference, or guide. Reply with one word.\n\n' + '$(cat "$file")'
    }" \
    --output text
done

# Generate embeddings for a corpus
ant embeddings create \
  --model claude-embed-v1 \
  --input "Your text here" \
  --output json | jq '.data[0].embedding'

Managing agents and sessions

# Create an agent (persistent configuration with tools and instructions)
ant agents create \
  --name "code-reviewer" \
  --model claude-sonnet-4-5 \
  --instructions "You are a code reviewer. Analyze diffs for bugs and security issues." \
  --tools "Read,Bash"

# List agents
ant agents list

# Run an agent on a task
ant agents run code-reviewer \
  --input "Review src/handler.go for security issues" \
  --output json

# Session management (continue conversations across runs)
ant sessions create --model claude-sonnet-4-5
ant sessions list
ant sessions send <session-id> --message "What did we discuss?"

ant in CI/CD

# .github/workflows/review.yml — PR review with ant
name: AI Review
on: [pull_request]
jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install ant
        run: curl -fsSL https://claude.ai/install-ant.sh | bash
      - name: Review PR
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          DIFF=$(git diff origin/main...HEAD)
          ant messages create \
            --max-tokens 2000 \
            --model claude-sonnet-4-5 \
            --message "{role: user, content: 'Review this diff for bugs and security issues. Output markdown.\n\n${DIFF}'}" \
            --output text > review.md
      - name: Post review
        uses: actions/github-script@v7
        with:
          script: |
            const fs = require('fs');
            const review = fs.readFileSync('review.md', 'utf8');
            github.rest.issues.createComment({
              ...context.repo,
              issue_number: context.issue.number,
              body: review
            });

Claude Code vs Codex CLI vs Kiro CLI

Intermediate

Instruction fileCLAUDE.mdAGENTS.mdAGENTS.md / steering

HooksYes (.claude/settings.json)NoYes (.kiro/hooks)
API scripting CLIant——

Claude Code's hooks feature is the main differentiator — it lets you automate actions (format, lint, test) after every file edit without manual intervention. If you're choosing between the three for a team, hooks + the ant API CLI make Claude Code strong for CI/CD automation.

Common mistakes

  • Not using CLAUDE.md. Without project instructions, Claude Code guesses your conventions. /init generates a starting point — refine it and commit it.
  • Unrestricted CI runs. In CI, always set --max-turns and --allowedTools. An unrestricted agent can run indefinitely and edit unexpected files.
  • Using Claude Code when ant is better. Claude Code is for agentic coding. For batch API calls (embeddings, classification, content generation at scale), ant is lighter and more scriptable.
  • Not setting hooks for formatting. Claude Code can produce unformatted code. A PostToolUse hook that runs your formatter after every edit saves manual cleanup.
  • Forgetting the API key in CI. Use a CI secret, not a hardcoded key. op read ... | ant --api-key-stdin keeps it out of environment and process lists.
  • Not using /compact in long sessions. Context fills up. /compact preserves key information while freeing space, letting a session continue longer.

Exercises

  1. Install Claude Code, run /init in a project, and refine the generated CLAUDE.md with your project's commands and conventions.
  2. Use Claude Code in headless mode to review uncommitted changes: claude -p "Review my uncommitted changes for bugs" --output-format text.
  3. Add a PostToolUse hook that runs gofmt (or prettier) after every file edit. Test it by asking Claude Code to edit a file and checking that it's formatted.
  4. Install ant, create an agent for code review, and use it to review a diff in a script. Output the review as JSON.
  5. Build a GitHub Actions workflow that runs claude -p on every PR to generate a markdown review comment. Set --max-turns 10 and --allowedTools "Read,Bash".

Mini-project: Automated PR review with hooks and CI

Build a complete PR review pipeline using Claude Code and ant. Requirements:

  • A CLAUDE.md that tells Claude Code how to review code in your project (focus areas, severity levels, output format).
  • A PostToolUse hook that runs your linter and test suite after every file edit during a review session.
  • A GitHub Actions workflow that uses claude -p to review every PR diff, outputs JSON with severity-rated findings, and posts a formatted comment on the PR.
  • Use ant to classify the review findings (bug, style, security, performance) and group the comment by category.
  • Add a --max-turns limit and --allowedTools restriction so the CI review can't run away or edit files.
