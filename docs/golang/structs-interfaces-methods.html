Go has no classes. Instead you compose structs, attach methods to them, and satisfy interfaces implicitly. Add generics and you have everything you need for reusable, type-safe code.

Structs and methods

type Account struct {
	Owner   string
	balance int   // lowercase = unexported (package-private)
}

// Value receiver: operates on a copy
func (a Account) Balance() int { return a.balance }

// Pointer receiver: can mutate the original
func (a *Account) Deposit(n int) { a.balance += n }

acc := Account{Owner: "Ada"}
acc.Deposit(100)             // Go auto-takes the address
fmt.Println(acc.Balance())   // → 100
Pick one receiver style per type. If any method needs a pointer receiver (to mutate, or because the struct is large), use pointer receivers for all of them. Mixing confuses callers and the method set rules.

Composition over inheritance

Intermediate Go embeds structs to reuse behavior — the embedded type's fields and methods are promoted:

type Timestamps struct {
	CreatedAt, UpdatedAt time.Time
}
type User struct {
	Timestamps        // embedded (no field name)
	Name string
}

u := User{Name: "Bo"}
u.CreatedAt = time.Now()   // promoted field, no u.Timestamps.CreatedAt needed

Interfaces are satisfied implicitly

An interface is a set of method signatures. A type satisfies it just by having those methods — no implements keyword, no declaration linking them. This decoupling is central to Go's design.

type Shape interface {
	Area() float64
}

type Circle struct{ R float64 }
func (c Circle) Area() float64 { return math.Pi * c.R * c.R }

type Rect struct{ W, H float64 }
func (r Rect) Area() float64 { return r.W * r.H }

// Both satisfy Shape automatically
shapes := []Shape{Circle{2}, Rect{3, 4}}
for _, s := range shapes { fmt.Printf("%.2f\n", s.Area()) }

The canonical example is the standard library's io.Writer — one method, Write([]byte) (int, error) — satisfied by files, network connections, buffers, HTTP responses, and os.Stdout alike. Accept the interface, and your code works with all of them.

The empty interface and any

// any (alias for interface{}) holds a value of any type
func describe(v any) {
	switch x := v.(type) {
	case int:    fmt.Println("int:", x)
	case string: fmt.Println("string:", x)
	default:     fmt.Printf("%T: %v\n", x, x)
	}
}
Common mistake: reaching for any to make something "flexible". It throws away compile-time type safety and forces type assertions everywhere. Prefer a small purposeful interface, or generics (below), and keep any for genuinely heterogeneous data like decoded JSON.

Generics

Advanced Since Go 1.18, functions and types can be parameterized by type, constrained by interfaces:

// A type parameter T constrained to comparable
func Index[T comparable](s []T, target T) int {
	for i, v := range s {
		if v == target { return i }
	}
	return -1
}

Index([]int{3, 5, 7}, 5)        // → 1
Index([]string{"a", "b"}, "b")  // → 1

// Constraints with the constraints-style union
type Number interface { ~int | ~int64 | ~float64 }
func Sum[T Number](xs []T) T {
	var total T
	for _, x := range xs { total += x }
	return total
}
Don't reach for generics first. If a plain function or an interface does the job clearly, use that. Generics shine for container-like code (collections, map/filter helpers) where the logic is identical across types.

Exercises

  • Define a Stringer (String() string) on a struct and watch fmt.Println use it automatically.
  • Write a function that accepts io.Writer and works with both a file and a bytes.Buffer.
  • Implement generic Map[T, U any](s []T, f func(T) U) []U and use it to turn []int into []string.

Mini-project: a shape registry

Define a Shape interface with Area() and Perimeter(). Implement Circle, Rect, Triangle. Write TotalArea(shapes []Shape) float64 and a generic Max[T constraints.Ordered] helper to find the largest shape by area — combining interfaces and generics in one small program.
