Testing ships with the toolchain — no framework to choose. Write _test.go files, run go test, and use table-driven tests, subtests, benchmarks, and fuzzing, all from the one testing package.

Your first test

// math.go
func Add(a, b int) int { return a + b }

// math_test.go  (same package, file ends in _test.go)
package main

import "testing"

func TestAdd(t *testing.T) {
	got := Add(2, 3)
	if got != 5 {
		t.Errorf("Add(2,3) = %d; want 5", got)
	}
}
go test ./...            # run everything
go test -v ./...         # verbose: show each test
go test -run TestAdd     # run tests matching a regex
# → ok  example.com/myapp  0.002s
t.Errorf records a failure and continues; t.Fatalf records and stops the test immediately (use it when later assertions would panic, e.g. after a nil check).

Table-driven tests

Beginner The idiomatic Go pattern: one test, a table of cases, each run as a named subtest.

func TestSlugify(t *testing.T) {
	cases := []struct {
		name, in, want string
	}{
		{"spaces", "Hello World", "hello-world"},
		{"punct", "A, B & C!", "a-b-c"},
		{"empty", "", ""},
	}
	for _, tc := range cases {
		t.Run(tc.name, func(t *testing.T) {
			if got := Slugify(tc.in); got != tc.want {
				t.Errorf("Slugify(%q) = %q; want %q", tc.in, got, tc.want)
			}
		})
	}
}
// go test -run TestSlugify/punct   ← run just one case

Coverage

go test -cover ./...                       # summary percentage
go test -coverprofile=cover.out ./...
go tool cover -html=cover.out              # open an annotated source view

Benchmarks

Intermediate Benchmark functions start with Benchmark and loop b.N times; the framework tunes N until the timing is stable.

func BenchmarkSlugify(b *testing.B) {
	for i := 0; i < b.N; i++ {
		Slugify("Hello World")
	}
}
go test -bench=. -benchmem ./...
# BenchmarkSlugify-8   3185402   376 ns/op   64 B/op   2 allocs/op
Common mistake: the compiler optimizing your benchmark away because the result is unused. Assign it to a package-level sink (var sink string; sink = Slugify(...)) so the work can't be eliminated.

Fuzzing

Advanced A fuzz test feeds randomized inputs to find panics and property violations:

func FuzzSlugify(f *testing.F) {
	f.Add("Hello World")              // seed corpus
	f.Fuzz(func(t *testing.T, s string) {
		out := Slugify(s)
		if strings.ContainsAny(out, " !&") {
			t.Errorf("slug %q still has forbidden chars", out)
		}
	})
}
// go test -fuzz=FuzzSlugify -fuzztime=30s

Test helpers and setup

func TestMain(m *testing.M) {   // once, around all tests in the package
	setup()
	code := m.Run()
	teardown()
	os.Exit(code)
}

func mustOpen(t *testing.T, p string) *os.File {
	t.Helper()                    // report failures at the CALLER's line
	f, err := os.Open(p)
	if err != nil { t.Fatalf("open %s: %v", p, err) }
	t.Cleanup(func() { f.Close() })  // runs when the test ends
	return f
}

Exercises

  • Convert three separate TestAdd* functions into one table-driven test with named subtests.
  • Benchmark two string-concatenation strategies (+ vs strings.Builder) with -benchmem and compare allocs.
  • Write a fuzz test for a parser and let it run 30 seconds; fix any panic it finds.
