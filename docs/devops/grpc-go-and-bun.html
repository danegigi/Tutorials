gRPC lets services talk to each other over a fast, strongly-typed, binary protocol defined by a shared schema. This lesson builds one service end to end as a polyglot system: a Protobuf schema as the contract, a Go server, and a type-safe Bun/TypeScript client — generated from the same .proto with modern tooling (Buf + ConnectRPC) that works cleanly in both ecosystems.

What gRPC is, and why a schema-first contract

Beginner REST sends JSON over HTTP/1.1 and the "contract" lives in documentation you hope is current. gRPC flips that: you write a Protocol Buffers schema, and both server and client generate code from it. The win:

  • One source of truth. The .proto defines messages and methods; drift between client and server becomes a compile error.
  • Compact + fast. Protobuf is a binary format over HTTP/2 (multiplexed, header-compressed) — smaller and faster than JSON/HTTP1.
  • Streaming. Unary, server-stream, client-stream, and bidirectional streaming are first-class.
  • Polyglot. Generate a Go server and a TypeScript client from the identical schema.
We use ConnectRPC rather than the classic grpc-go + protoc-gen-grpc stack. Connect speaks the gRPC, gRPC-Web, and its own HTTP/JSON protocol from one server on one port — and its TypeScript client runs on Bun, in Node, and in browsers with no native addon. That interop is what makes a Go server + Bun client painless.

The schema — the contract

Define the service once. This is a greeter with a unary call and a server-streaming call:

# proto/greet/v1/greet.proto
syntax = "proto3";

package greet.v1;
option go_package = "example/gen/greet/v1;greetv1";

message GreetRequest  { string name = 1; }
message GreetResponse { string greeting = 1; }

service GreetService {
  rpc Greet(GreetRequest) returns (GreetResponse);
  // server streaming: emit a countdown of greetings
  rpc GreetStream(GreetRequest) returns (stream GreetResponse);
}
Field numbers (= 1, = 2) are the wire identity, not the names. Never renumber or reuse a field number in a deployed schema — it silently corrupts decoding. To remove a field, mark it reserved.

Code generation with Buf

Intermediate Buf is the modern replacement for raw protoc: it lints schemas, detects breaking changes, and drives codegen from a config file. Install the CLI, then declare the plugins for each language:

# buf.yaml — the module
version: v2
modules:
  - path: proto
# buf.gen.yaml — what to generate
version: v2
plugins:
  # Go: messages + Connect service code
  - remote: buf.build/protocolbuffers/go
    out: gen
    opt: paths=source_relative
  - remote: buf.build/connectrpc/go
    out: gen
    opt: paths=source_relative
  # TypeScript: messages + Connect client (for Bun)
  - remote: buf.build/bufbuild/es
    out: web/src/gen
    opt: target=ts
# generate everything in one command
buf lint          # catch schema problems early
buf generate      # writes Go into gen/ and TS into web/src/gen/
The remote: plugins run on Buf's hosted registry, so you don't install a protoc toolchain locally — great for a mixed Go/Bun repo. For fully offline builds, switch to local: plugins and install the binaries.

The Go server

ConnectRPC generates a handler interface. You implement it and mount it on a standard net/http server — no special gRPC server object:

// cmd/server/main.go
package main

import (
    "context"
    "log"
    "net/http"

    "connectrpc.com/connect"
    greetv1 "example/gen/greet/v1"
    "example/gen/greet/v1/greetv1connect"
    "golang.org/x/net/http2"
    "golang.org/x/net/http2/h2c"
)

type GreetServer struct{}

func (s *GreetServer) Greet(
    ctx context.Context, req *connect.Request[greetv1.GreetRequest],
) (*connect.Response[greetv1.GreetResponse], error) {
    name := req.Msg.Name
    if name == "" {
        return nil, connect.NewError(connect.CodeInvalidArgument,
            errors.New("name is required"))
    }
    return connect.NewResponse(&greetv1.GreetResponse{
        Greeting: "Hello, " + name + "!",
    }), nil
}

func main() {
    mux := http.NewServeMux()
    path, handler := greetv1connect.NewGreetServiceHandler(&GreetServer{})
    mux.Handle(path, handler)

    // h2c serves HTTP/2 without TLS for local dev (gRPC needs HTTP/2)
    log.Println("listening on :8080")
    http.ListenAndServe(":8080", h2c.NewHandler(mux, &http2.Server{}))
}
# deps + run
go mod init example
go get connectrpc.com/connect golang.org/x/net/http2
go run ./cmd/server
Plain gRPC requires HTTP/2. For local dev without certificates, wrap the mux in h2c (HTTP/2 cleartext). In production you terminate TLS (next section) — don't ship h2c to the open internet.

The Bun / TypeScript client

Connect's TypeScript client runs natively on Bun. Install the runtime packages, create a transport pointing at the server, and call the generated methods — fully typed:

bun add @connectrpc/connect @connectrpc/connect-node @bufbuild/protobuf
// web/src/client.ts
import { createClient } from "@connectrpc/connect";
import { createGrpcTransport } from "@connectrpc/connect-node";
import { GreetService } from "./gen/greet/v1/greet_pb";

const transport = createGrpcTransport({
  baseUrl: "http://localhost:8080",
});

const client = createClient(GreetService, transport);

// unary call — req/res are typed from the schema
const res = await client.greet({ name: "Ada" });
console.log(res.greeting); // "Hello, Ada!"

// server streaming — async iterator
for await (const msg of client.greetStream({ name: "Ada" })) {
  console.log(msg.greeting);
}
bun run web/src/client.ts

Change the schema (say, add a field), run buf generate, and both the Go server and this Bun client get the update — a mismatch now fails to compile instead of failing at 3 a.m. in production.

Running it locally with TLS

Advanced HTTP/2 in production means TLS. Generate a dev cert, serve with ListenAndServeTLS, and point the client at https://:

# a local cert (mkcert installs a trusted local CA)
mkcert localhost
# → localhost.pem + localhost-key.pem
// Go server — swap the h2c line for:
http.ListenAndServeTLS(":8443", "localhost.pem", "localhost-key.pem", mux)
// Bun client — https base URL; Connect negotiates HTTP/2 over TLS automatically
const transport = createGrpcTransport({ baseUrl: "https://localhost:8443" });

Debug a running service without writing a client using grpcurl — if you enable server reflection it can list and call methods:

grpcurl -d '{"name":"Ada"}' localhost:8080 greet.v1.GreetService/Greet

Errors, deadlines, and interceptors

Production gRPC leans on three things REST handles ad hoc:

  • Status codes. Return connect.NewError(connect.CodeNotFound, …) rather than a 404 body; clients branch on the typed code.
  • Deadlines. The client sets a timeout that propagates to the server as a context deadline — set one on every call so a slow dependency can't hang a request forever.
  • Interceptors. The gRPC equivalent of middleware — logging, auth, metrics — applied uniformly on both server and client.
// client: a 5s deadline + a logging interceptor
import { Code, ConnectError } from "@connectrpc/connect";
try {
  await client.greet({ name: "Ada" }, { timeout: 5000 });
} catch (e) {
  if (e instanceof ConnectError && e.code === Code.DeadlineExceeded) {
    console.error("server too slow");
  }
}

Deploying it

Containerize the Go server like any HTTP service; the only gRPC-specific rules are at the edge:

  • Your load balancer / ingress must support HTTP/2 end-to-end (an L7 proxy that downgrades to HTTP/1.1 breaks gRPC). On Kubernetes, annotate the Ingress for gRPC/HTTP2 backends.
  • gRPC holds long-lived connections, so naive connection-count load balancing sends all traffic to one pod. Use an L7/gRPC-aware balancer (or client-side LB / a mesh) that balances per-request.
  • Expose a health check — the standard gRPC health service — and wire it to your orchestrator's probes.
  • Put buf lint and buf breaking in CI so a schema change that would break existing clients fails the build.

Common mistakes

  • Serving plain gRPC over HTTP/1.1. gRPC needs HTTP/2 — use h2c locally and real TLS in prod; an HTTP/1-only proxy in front silently breaks it.
  • Reusing or renumbering Protobuf field numbers. The number is the wire identity. Reserve removed numbers; never recycle them.
  • Editing generated code. Files under gen/ are overwritten by buf generate. Change the .proto and regenerate.
  • No deadlines. Without a client timeout, a hung server dependency ties up the caller indefinitely. Set a deadline on every RPC.
  • Connection-count load balancing. Long-lived HTTP/2 connections defeat it; use a gRPC-aware L7 balancer so requests spread across pods.
  • Returning errors as normal responses. Use gRPC status codes so clients can branch on NotFound vs InvalidArgument vs Internal.

Exercises

  • Write the greet.proto schema, set up buf.yaml/buf.gen.yaml, and run buf lint + buf generate; confirm Go and TS code appear.
  • Implement the Go Greet handler, serve it with h2c, and call it from a Bun client — print the greeting.
  • Add the server-streaming GreetStream method and consume it in Bun with for await.
  • Add TLS with mkcert and switch the client to https://; verify it still works.
  • Return CodeInvalidArgument for an empty name and handle that specific code on the Bun side; add a 2-second client deadline and trigger DeadlineExceeded.

Mini-project: a polyglot todo service

Build a small todo service with a Go server and a Bun CLI client, both from one schema:

  • Define todo/v1/todo.proto with CreateTodo, ListTodos (unary), and WatchTodos (server stream that emits on each change).
  • Generate Go + TS with Buf; wire buf lint and buf breaking into a CI step.
  • Implement the Go server over an in-memory store, with proper status codes (AlreadyExists, NotFound) and a logging interceptor.
  • Build a Bun CLI that creates todos, lists them, and tails WatchTodos live — all type-safe against the generated client.
  • Add TLS, a gRPC health check, and a Dockerfile for the server; document how an HTTP/2-aware ingress would route it.

You'll have a working polyglot gRPC system — Go and Bun sharing one contract — plus the operational pieces (TLS, health, CI schema checks) that make it production-ready.
