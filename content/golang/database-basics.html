Go talks to SQL databases through database/sql — a driver-agnostic interface with connection pooling built in. Learn safe queries, the pool knobs that matter, and when a typed ORM like Ent earns its keep.

Connecting

import (
	"database/sql"
	_ "github.com/mattn/go-sqlite3"   // blank import registers the driver
)

db, err := sql.Open("sqlite3", "app.db")
if err != nil { log.Fatal(err) }
defer db.Close()

if err := db.Ping(); err != nil {    // Open is lazy — Ping actually connects
	log.Fatal(err)
}
sql.DB is a pool, not a single connection. Create one per database for the lifetime of your program and share it — do not open a new one per request.

Querying safely

// Single row
var name string
err := db.QueryRow("SELECT name FROM users WHERE id = ?", id).Scan(&name)
if err == sql.ErrNoRows {
	// not found
}

// Many rows
rows, err := db.Query("SELECT id, name FROM users WHERE active = ?", true)
if err != nil { return err }
defer rows.Close()                   // ALWAYS — leaks a connection otherwise

for rows.Next() {
	var u User
	if err := rows.Scan(&u.ID, &u.Name); err != nil { return err }
	users = append(users, u)
}
return rows.Err()                    // check for mid-iteration errors
Never build SQL with string concatenation. "... WHERE name = '" + input + "'" is a SQL-injection hole. Always use placeholders (? for SQLite/MySQL, $1 for Postgres) and pass values as arguments — the driver escapes them.

Writes and results

res, err := db.Exec("INSERT INTO users(name, email) VALUES(?, ?)", name, email)
if err != nil { return err }
id, _ := res.LastInsertId()
n, _ := res.RowsAffected()

Transactions

tx, err := db.Begin()
if err != nil { return err }
defer tx.Rollback()                  // no-op if already committed

if _, err := tx.Exec("UPDATE accounts SET bal = bal - ? WHERE id = ?", amt, from); err != nil {
	return err
}
if _, err := tx.Exec("UPDATE accounts SET bal = bal + ? WHERE id = ?", amt, to); err != nil {
	return err
}
return tx.Commit()

Pool configuration

Intermediate The defaults are rarely right for production:

db.SetMaxOpenConns(25)                 // cap concurrent connections
db.SetMaxIdleConns(25)                 // keep warm connections ready
db.SetConnMaxLifetime(5 * time.Minute) // recycle to survive DB restarts/LB
Common mistake: leaving MaxOpenConns unbounded (the default). Under load Go will open thousands of connections and exhaust the database's own connection limit. Set it to something your DB can handle.

When to use an ORM: Ent

Advanced For large schemas with lots of relations, a code-generating ORM like Ent gives you a typed query builder and migrations. You define the schema in Go, run codegen, and get compile-checked queries:

// schema/user.go — declarative
func (User) Fields() []ent.Field {
	return []ent.Field{
		field.String("name"),
		field.String("email").Unique(),
	}
}
// go generate ./ent  → generated client

// Typed queries, no raw SQL strings
u, err := client.User.Create().SetName("Ada").SetEmail("ada@x.com").Save(ctx)
users, err := client.User.Query().Where(user.NameHasPrefix("A")).All(ctx)

The trade-off: a build step and generated code in your repo, in exchange for eliminating a whole class of hand-written-SQL bugs. For small apps, plain database/sql (optionally with sqlx for struct scanning) is simpler.

Exercises

  • Create a SQLite users table, insert three rows with placeholders, and query them back into a []User.
  • Wrap two writes in a transaction and prove a mid-transaction error rolls both back.
  • Set MaxOpenConns(2), fire 10 concurrent queries, and observe them queueing.
