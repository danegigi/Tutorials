Go compiles to a single static binary, which makes it a superb language for command-line tools. Parse flags with the stdlib flag package, structure subcommands, set exit codes, and read stdin — then ship one file that runs anywhere.

Flags with the standard library

package main

import (
	"flag"
	"fmt"
)

func main() {
	name := flag.String("name", "world", "who to greet")
	count := flag.Int("n", 1, "number of greetings")
	upper := flag.Bool("upper", false, "uppercase output")
	flag.Parse()

	msg := fmt.Sprintf("Hello, %s!", *name)
	if *upper { msg = strings.ToUpper(msg) }
	for i := 0; i < *count; i++ { fmt.Println(msg) }
}
go run . -name Ada -n 2 -upper
# → HELLO, ADA!
# → HELLO, ADA!

go run . -h          # flag auto-generates usage from the descriptions

Positional arguments after the flags are available via flag.Args() (and flag.Arg(0)).

Exit codes

Beginner A CLI signals success/failure through its exit code — 0 success, non-zero failure. Shell scripts and CI depend on it.

func main() {
	if err := run(); err != nil {
		fmt.Fprintln(os.Stderr, "error:", err)   // errors go to STDERR
		os.Exit(1)
	}
}
func run() error { /* real work; return error */ return nil }
Common mistakes: (1) printing errors to stdout instead of stderr — it corrupts piped output. (2) calling os.Exit deep in the code, which skips every defer. Keep os.Exit in main only, and return errors up to it.

Reading stdin (pipe-friendly tools)

// Behave like a Unix filter: read stdin, transform, write stdout
scanner := bufio.NewScanner(os.Stdin)
for scanner.Scan() {
	fmt.Println(strings.ToUpper(scanner.Text()))
}
// echo "hi" | go run .   → HI
// cat file.txt | go run .  works too

Subcommands

Intermediate For a tool with multiple verbs (git-style), give each its own FlagSet:

func main() {
	if len(os.Args) < 2 {
		fmt.Fprintln(os.Stderr, "usage: tool <add|list> ...")
		os.Exit(2)
	}
	switch os.Args[1] {
	case "add":
		fs := flag.NewFlagSet("add", flag.ExitOnError)
		prio := fs.Int("p", 1, "priority")
		fs.Parse(os.Args[2:])
		add(fs.Arg(0), *prio)
	case "list":
		list()
	default:
		fmt.Fprintf(os.Stderr, "unknown command %q\n", os.Args[1])
		os.Exit(2)
	}
}
For large CLIs with nested commands, completion, and help, the community standard is Cobra (used by kubectl, Hugo, GitHub CLI). Reach for it when the stdlib flag plumbing starts to hurt — not before.

Shipping the binary

go build -o tool .                 # build for your platform
GOOS=linux GOARCH=amd64 go build -o tool-linux .   # cross-compile
go install .                       # install into $GOBIN for use anywhere

The result is one self-contained executable with no runtime to install — copy it to a server and run it.

Exercises

  • Write a wc-style tool: count lines/words/bytes of stdin, with -l/-w/-c flags.
  • Make it exit 1 and print to stderr when given a path that doesn't exist.
  • Add a version subcommand that prints a build-time version string.

Mini-project: a note-taking CLI

Build notes with subcommands add "text", list, done <id>, and rm <id>, persisting to a JSON file in $HOME. Use per-subcommand FlagSets, correct exit codes, errors to stderr, and cross-compile it for Linux and macOS. You now have a real tool you'd actually use.
