Go deliberately has very few control structures: one loop keyword, an if with an init statement, a switch with no fallthrough by default, and defer for cleanup. Fewer forms, fewer surprises.

if / else

if x > 0 {
	fmt.Println("positive")
} else if x < 0 {
	fmt.Println("negative")
} else {
	fmt.Println("zero")
}

// if with an init statement — scopes the variable to the if/else
if v, ok := m["key"]; ok {
	fmt.Println("found", v)
}  // v and ok are out of scope here
The if err := doThing(); err != nil { return err } pattern is everywhere in Go. The init statement keeps err scoped to the check, so it can't leak into the rest of the function.

for — the only loop

// Classic three-clause
for i := 0; i < 5; i++ { }

// While-style
for n < 100 { n *= 2 }

// Infinite (break to exit)
for { if done() { break } }

// Range over slice, map, string, channel
for i, v := range []string{"a", "b"} { fmt.Println(i, v) }
for key, val := range myMap { }
for _, r := range "héllo" { }   // r is a rune (code point), not a byte

// Range over an integer (Go 1.22+)
for i := range 3 { fmt.Println(i) }  // 0 1 2
Common mistake: ranging a string with index arithmetic expecting characters. A string is UTF-8 bytes; len(s) is byte length and s[i] is a byte. Use range (which yields runes) or []rune(s) when you need code points.

switch

// No automatic fallthrough — each case breaks implicitly
switch day {
case "Sat", "Sun":
	fmt.Println("weekend")
default:
	fmt.Println("weekday")
}

// Expression-less switch = clean if/else chain
switch {
case score >= 90:
	grade = "A"
case score >= 80:
	grade = "B"
default:
	grade = "F"
}

// Type switch (with interfaces)
switch v := any.(type) {
case int:
	fmt.Println("int", v)
case string:
	fmt.Println("string", v)
}

Use the explicit fallthrough keyword only when you really want the next case to run too — it's rare.

defer, panic, recover

Intermediate defer schedules a call to run when the surrounding function returns, in LIFO order. It's the idiomatic way to guarantee cleanup:

f, err := os.Open("data.txt")
if err != nil { return err }
defer f.Close()   // runs no matter how the function exits
// ... use f ...
// defer sees the final named return value — useful for wrapping errors
func process() (err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("recovered: %v", r)
		}
	}()
	mightPanic()
	return nil
}
Common mistake: defer inside a loop. Deferred calls stack up until the function returns, not the loop iteration — opening 10,000 files in a loop with defer f.Close() keeps all 10,000 open. Close explicitly inside the loop, or wrap each iteration in its own function.

Reserve panic/recover for truly unrecoverable situations and for stopping a goroutine from crashing a server — not for ordinary error handling, which uses returned error values (next lesson).

Exercises

  • Rewrite an if/else-if ladder grading scores into an expression-less switch.
  • Count bytes vs runes in "café" and explain the difference.
  • Write a function that opens three files and closes each one correctly inside a loop (not with a leaking defer).
