A Go program compiles to one static binary with no runtime dependencies — which makes deployment unusually simple. Learn optimized builds, cross-compilation, tiny Docker images, and running as a managed service.

Building for release

# Strip debug info for a smaller binary
go build -ldflags="-s -w" -o app .

# Embed a version at build time
go build -ldflags="-X main.version=$(git describe --tags)" -o app .
// main.go
var version = "dev"   // overwritten by -ldflags -X
func main() { fmt.Println("version:", version) }

Cross-compilation

Beginner Set GOOS and GOARCH to build for any target from any machine — no cross-toolchain to install:

GOOS=linux   GOARCH=amd64 go build -o app-linux-amd64 .
GOOS=linux   GOARCH=arm64 go build -o app-linux-arm64 .
GOOS=darwin  GOARCH=arm64 go build -o app-macos .
GOOS=windows GOARCH=amd64 go build -o app.exe .

go tool dist list    # every supported GOOS/GOARCH pair
Common gotcha: cross-compiling fails or produces a dynamically-linked binary when your code uses cgo (C bindings — e.g. the mattn/go-sqlite3 driver). Set CGO_ENABLED=0 for a pure-Go static build, or use a pure-Go driver (e.g. modernc.org/sqlite) so cross-compilation stays trivial.

A minimal Docker image

Intermediate Multi-stage builds compile in a full Go image, then copy just the binary into a tiny base — a few MB total:

# Dockerfile
FROM golang:1.23 AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download                 # cached layer: deps change rarely
COPY . .
RUN CGO_ENABLED=0 go build -ldflags="-s -w" -o /app .

FROM gcr.io/distroless/static-debian12   # no shell, no package manager
COPY --from=build /app /app
USER nonroot:nonroot
ENTRYPOINT ["/app"]
docker build -t myapp .
docker run -p 8080:8080 myapp
Order the Dockerfile so go.mod/go.sum and go mod download come before COPY . .. Then a code change doesn't invalidate the dependency-download layer, and rebuilds are seconds instead of minutes.

Configuration via environment

port := os.Getenv("PORT")
if port == "" { port = "8080" }      // sensible default
dsn := os.Getenv("DATABASE_URL")     // never hard-code secrets

Twelve-factor style: read config from the environment, keep secrets out of the image, and inject them at runtime (Compose env, Kubernetes Secrets, or your platform's secret store).

Running as a systemd service

Intermediate On a plain Linux server, systemd keeps your binary running and restarts it on crash or reboot:

# /etc/systemd/system/myapp.service
[Unit]
Description=My Go App
After=network.target

[Service]
ExecStart=/usr/local/bin/myapp
Restart=always
Environment=PORT=8080
User=myapp

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now myapp
sudo systemctl status myapp
journalctl -u myapp -f           # follow its logs

Graceful shutdown

// Drain in-flight requests on SIGTERM instead of dropping them
srv := &http.Server{Addr: ":8080", Handler: mux}
go srv.ListenAndServe()

stop := make(chan os.Signal, 1)
signal.Notify(stop, os.Interrupt, syscall.SIGTERM)
<-stop

ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
srv.Shutdown(ctx)                // waits for active requests, then exits

Exercises

  • Build your app for Linux/arm64 with CGO_ENABLED=0 and confirm it's statically linked (file app).
  • Write the multi-stage Dockerfile and compare the image size to the full golang base.
  • Add SIGTERM graceful shutdown and verify an in-flight request completes during a redeploy.

Mini-project: ship the TODO API

Take the SQLite-backed TODO API, switch to a pure-Go SQLite driver so CGO_ENABLED=0 works, add graceful shutdown and env-based config, build a distroless Docker image, and write a systemd unit for the non-container path. You've now taken one program from go run to a deployable, restart-safe service.
