Go has no exceptions for ordinary failures. Errors are plain values you return and check. Learn the (result, error) convention, wrapping with %w, and errors.Is/errors.As for inspecting error chains.

Errors are values

func readConfig(path string) ([]byte, error) {
	data, err := os.ReadFile(path)
	if err != nil {
		return nil, err   // propagate up
	}
	return data, nil
}

data, err := readConfig("app.yaml")
if err != nil {
	log.Fatalf("config: %v", err)
}

The error type is just an interface with one method:

type error interface { Error() string }
Common mistake: ignoring the error with data, _ := readConfig(...). Occasionally justified, but each one is a decision — go vet and linters like errcheck flag unchecked errors so they're a conscious choice, not an oversight.

Creating errors

// Simple
errors.New("something failed")

// Formatted
fmt.Errorf("open %s: permission denied", path)

// Sentinel errors — exported values callers can compare against
var ErrNotFound = errors.New("not found")

func Get(id string) (*Item, error) {
	if _, ok := store[id]; !ok {
		return nil, ErrNotFound
	}
	// ...
}

Wrapping with %w

Intermediate Wrapping adds context while preserving the original error so callers can still inspect it. Use the %w verb:

func loadUser(id string) (*User, error) {
	u, err := Get(id)
	if err != nil {
		return nil, fmt.Errorf("loadUser %q: %w", id, err)
	}
	return u, nil
}

// The message chains:  loadUser "42": not found

Inspecting errors: Is and As

_, err := loadUser("42")

// errors.Is: does the chain contain this sentinel?
if errors.Is(err, ErrNotFound) {
	http.Error(w, "no such user", 404)
	return
}

// errors.As: extract a specific error TYPE from the chain
var pathErr *os.PathError
if errors.As(err, &pathErr) {
	fmt.Println("failing path:", pathErr.Path)
}
Common mistake: comparing wrapped errors with == (e.g. err == ErrNotFound). Once an error is wrapped with %w, equality fails. Always use errors.Is for sentinels and errors.As for types — they walk the whole chain.

Custom error types

type ValidationError struct {
	Field string
	Msg   string
}
func (e *ValidationError) Error() string {
	return fmt.Sprintf("%s: %s", e.Field, e.Msg)
}

// Return it, then recover it with errors.As
err := &ValidationError{Field: "email", Msg: "required"}
var ve *ValidationError
if errors.As(err, &ve) { fmt.Println(ve.Field) }  // → email

When to panic

Reserve panic for programmer errors and truly impossible states (a nil map you control, a corrupt invariant), and for the top of a goroutine where you recover to keep a server alive. Everything a caller might reasonably handle — bad input, missing file, network failure — returns an error.

Exercises

  • Define ErrEmpty and return it from a parser; have the caller branch on errors.Is.
  • Wrap a file-open error with context three layers deep and confirm errors.As(&pathErr) still extracts the *os.PathError.
  • Write a ValidationError with a Fields map[string]string and aggregate several field errors into one.

Mini-project: a validating form parser

Parse a map[string]string of form fields into a SignupRequest struct. Collect every validation failure into a custom Errors type (a slice of *ValidationError) that itself satisfies error. Return the aggregate, and in the caller use errors.As to render per-field messages — the pattern behind real web form validation.
