The Concurrency lesson introduced context; this is the full treatment. Context is how a Go program carries cancellation, deadlines, and request-scoped values across API boundaries — the mechanism that lets a cancelled HTTP request tear down every goroutine and database call it spawned.

Why context exists

Beginner When a request is cancelled (the client disconnects, a timeout fires), everything it started should stop: the DB query, the outbound API call, the background goroutine. Context propagates that "stop now" signal down the whole call tree so nothing keeps working on an answer no one wants.

The four constructors

context.Background()   // the root — top of main, tests, init
context.TODO()         // placeholder when you haven't wired it through yet

ctx, cancel := context.WithCancel(parent)              // cancel manually
ctx, cancel := context.WithTimeout(parent, 2*time.Second)  // cancel after a duration
ctx, cancel := context.WithDeadline(parent, someTime)      // cancel at a time
defer cancel()         // ALWAYS defer cancel — it frees resources
The most common context bug: not calling cancel. WithTimeout/WithCancel start a goroutine/timer that lives until cancel is called — forgetting it leaks resources, and go vet flags it ("the cancel function is not used on all paths"). Always defer cancel() immediately, even when the timeout will fire on its own.

Honoring cancellation

func worker(ctx context.Context) error {
	for {
		select {
		case <-ctx.Done():            // cancelled or timed out
			return ctx.Err()         // context.Canceled or context.DeadlineExceeded
		case job := <-jobs:
			process(job)
		}
	}
}

// ctx.Done() returns a channel closed on cancellation.
// ctx.Err() tells you WHY: Canceled vs DeadlineExceeded.

Propagation through the stack

Intermediate Context flows as the first argument of every function that does I/O or might block. The stdlib already accepts it everywhere:

func handler(w http.ResponseWriter, r *http.Request) {
	ctx := r.Context()                       // cancelled when the client disconnects

	// Pass it down — the DB query aborts if the request is cancelled
	rows, err := db.QueryContext(ctx, "SELECT ...")

	// And to outbound calls — the fetch aborts too
	req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
	resp, err := http.DefaultClient.Do(req)
}
A derived context can only be more restrictive than its parent: a child added a shorter timeout, or was cancelled directly. Cancelling a parent cancels all its children; cancelling a child never affects the parent. This forms a cancellation tree that mirrors your call tree.

Request-scoped values

// Store (middleware) and retrieve (handler) a request-scoped value
type ctxKey string
const userKey ctxKey = "user"

ctx = context.WithValue(ctx, userKey, currentUser)
u, ok := ctx.Value(userKey).(*User)
Use context values sparingly and correctly: only for request-scoped data that crosses API boundaries (a request ID, the authenticated user, a trace span) — never for optional function parameters. Always use a private, non-string key type (like ctxKey above) so your keys can't collide with another package's. Passing config or dependencies through context instead of explicit arguments is an anti-pattern.

The rules

  • Pass context as the first parameter, named ctx — never store it in a struct.
  • Don't pass a nil context; use context.TODO() if you don't have one yet.
  • The same context can go to multiple goroutines simultaneously — it's safe for concurrent use.
  • cancel is idempotent and safe to call multiple times; always defer it.

Exercises

  • Write a function that does work in a loop and returns ctx.Err() promptly when cancelled.
  • Give an HTTP handler a 500ms WithTimeout around a slow operation and return 504 on DeadlineExceeded.
  • Add a request-ID to the context in middleware with a private key type and read it in a downstream handler.

Mini-project: a cancellable fan-out

Build a function that fetches N URLs concurrently under a single parent context with a global timeout. When the deadline fires (or the first hard error occurs), every in-flight request must abort via NewRequestWithContext — no goroutine keeps running. Return partial results plus ctx.Err(), and prove with the race detector that cancellation is clean and leak-free.
