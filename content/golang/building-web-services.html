The HTTP Servers lesson got you serving requests. This one is about everything between "it responds" and "it survives production": the Go 1.22 router that finally made net/http enough on its own, middleware you can actually compose, timeouts that stop a slow client from exhausting you, graceful shutdown that doesn't drop in-flight requests, and structured logging with slog carried through context.

The 1.22 router: method + path patterns beginner

Before Go 1.22 the stdlib mux couldn't match methods or capture path variables, which is why everyone reached for a third-party router. Now it can:

mux := http.NewServeMux()

mux.HandleFunc("GET /users/{id}", func(w http.ResponseWriter, r *http.Request) {
    id := r.PathValue("id") // typed path capture
    fmt.Fprintf(w, "user %s", id)
})
mux.HandleFunc("POST /users", createUser)
mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
    w.WriteHeader(http.StatusOK)
})

// {$} matches ONLY the exact path (no subpaths); {rest...} is a wildcard tail.
mux.HandleFunc("GET /{$}", home)              // "/" exactly
mux.HandleFunc("GET /static/{file...}", serve) // /static/a/b.css
For many services, the stdlib mux is now all you need — no framework. Reach for chi/echo/gin only when you want their batteries (binding, validation, large middleware ecosystems), not because routing forces you to.

Composable middleware intermediate

Middleware in Go is just func(http.Handler) http.Handler. Compose a chain so order is explicit and readable:

type Middleware func(http.Handler) http.Handler

func Chain(h http.Handler, mw ...Middleware) http.Handler {
    for i := len(mw) - 1; i >= 0; i-- { // apply in reverse so the first listed runs first
        h = mw[i](h)
    }
    return h
}

func Logging(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        rw := &statusRecorder{ResponseWriter: w, status: 200}
        next.ServeHTTP(rw, r)
        slog.InfoContext(r.Context(), "request",
            "method", r.Method, "path", r.URL.Path,
            "status", rw.status, "dur", time.Since(start))
    })
}

// Capture the status code (ResponseWriter won't tell you otherwise).
type statusRecorder struct {
    http.ResponseWriter
    status int
}
func (r *statusRecorder) WriteHeader(c int) { r.status = c; r.ResponseWriter.WriteHeader(c) }

handler := Chain(mux, Logging, Recover, RequestID)

Timeouts: the ones that actually matter intermediate

A default http.Server{} has no timeouts. One slow or malicious client can hold a connection open forever and exhaust your server. Always set them:

srv := &http.Server{
    Addr:              ":8080",
    Handler:           handler,
    ReadHeaderTimeout: 5 * time.Second,  // Slowloris protection
    ReadTimeout:       15 * time.Second,
    WriteTimeout:      15 * time.Second,
    IdleTimeout:       60 * time.Second,
}

For per-request deadlines on your own work (DB calls, upstreams), derive a context with a timeout and pass it down — never block forever:

func handler(w http.ResponseWriter, r *http.Request) {
    ctx, cancel := context.WithTimeout(r.Context(), 3*time.Second)
    defer cancel()
    row := db.QueryRowContext(ctx, "SELECT ...") // cancels at 3s or on client disconnect
    _ = row
}

Graceful shutdown advanced

On deploy or SIGTERM, you want to stop accepting new connections but let in-flight requests finish. srv.Shutdown(ctx) does exactly that:

func main() {
    srv := &http.Server{Addr: ":8080", Handler: handler /* + timeouts */}

    go func() {
        if err := srv.ListenAndServe(); err != nil && err != http.ErrServerClosed {
            slog.Error("listen", "err", err)
            os.Exit(1)
        }
    }()

    // Wait for SIGINT/SIGTERM.
    ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
    defer stop()
    <-ctx.Done()

    // Give in-flight requests up to 10s to finish.
    shutdownCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
    defer cancel()
    if err := srv.Shutdown(shutdownCtx); err != nil {
        slog.Error("forced shutdown", "err", err) // deadline hit — some requests cut off
    }
    slog.Info("stopped cleanly")
}
Set the shutdown timeout shorter than your orchestrator's termination grace period (Kubernetes defaults to 30s). If Shutdown's deadline is longer, the orchestrator SIGKILLs you mid-request and the graceful logic was pointless.

Structured logging with slog + context advanced

log/slog (Go 1.21+) gives you structured, leveled logs with no dependency. The pattern that scales: put a request-scoped logger (with a request ID) into the context, and every layer logs through it so lines correlate.

logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: slog.LevelInfo}))
slog.SetDefault(logger)

type ctxKey struct{}

func WithRequestID(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        id := r.Header.Get("X-Request-ID")
        if id == "" { id = randomID() }
        l := slog.With("request_id", id)
        ctx := context.WithValue(r.Context(), ctxKey{}, l)
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}

// Any handler/service pulls the correlated logger back out:
func L(ctx context.Context) *slog.Logger {
    if l, ok := ctx.Value(ctxKey{}).(*slog.Logger); ok { return l }
    return slog.Default()
}

func createUser(w http.ResponseWriter, r *http.Request) {
    L(r.Context()).Info("creating user", "name", "Ada") // carries request_id automatically
}

Common mistakes

  • No server timeouts. The zero-value http.Server will happily let a client hold a connection open indefinitely. Always set ReadHeaderTimeout at minimum.
  • Ignoring http.ErrServerClosed. ListenAndServe returns that error on a clean Shutdown — treating it as a failure makes graceful shutdown log a false error (or exit non-zero).
  • Writing the body before the status. The first Write implicitly sends 200; a later WriteHeader(500) is ignored and logs a warning. Set the status first.
  • Shutdown timeout longer than the orchestrator grace. You get SIGKILLed anyway. Keep it shorter.
  • Logging without correlation. Unstructured log.Printf lines you can't tie to a request are nearly useless under load. Carry a request ID.
  • Putting a *slog.Logger in context as the ONLY copy. Fine for request scope, but don't make background goroutines depend on a request's context that may already be cancelled.

Exercises

  1. Convert a service from a third-party router to the stdlib 1.22 mux with {id} path values and method matching. Confirm the routes still behave.
  2. Write a Recover middleware that turns a panic into a 500 and logs the stack through the context logger instead of crashing the server.
  3. Add all four server timeouts, then simulate a slow client (nc that sends headers one byte at a time) and confirm ReadHeaderTimeout cuts it off.
  4. Implement graceful shutdown and verify with a 5-second handler + curl in flight when you send SIGTERM — the request should finish, not drop.
