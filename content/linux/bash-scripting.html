A shell script is just a file of the same commands you type at the prompt, saved so you can run them again and share them. The step up from one-liner to robust script is small but important: a shebang, careful quoting, a few control structures, and the safety line set -euo pipefail that turns silent failures into loud ones. This lesson builds up to a real, re-runnable backup script you would trust on a server.

The shebang and running a script

Beginner The first line, the shebang, tells the system which interpreter to use. Then make the file executable and run it.

cat > hello.sh <<'EOF'
#!/usr/bin/env bash
echo "Hello from $(hostname)"
EOF
chmod +x hello.sh
./hello.sh
# -> Hello from web-01
Use #!/usr/bin/env bash rather than #!/bin/bash: it finds bash via PATH, which matters on systems (like some BSDs or Nix) where bash is not in /bin. Use #!/bin/sh only if you are deliberately writing portable POSIX shell without bash features.

Variables and quoting

Beginner Assign with no spaces around =. Expand with $name or ${name}. The single most common bug in shell scripts is forgetting to quote expansions.

name="Ada Lovelace"       # no spaces around =
echo "$name"              # QUOTED: prints the whole value
# -> Ada Lovelace
echo $name                # UNQUOTED: word-split into two arguments
# -> Ada Lovelace    (looks the same here, but breaks with globs/extra spaces)

dir="/var/log/my app"
ls "$dir"                 # correct: one argument
ls $dir                   # WRONG: ls gets '/var/log/my' and 'app' separately

# Command substitution captures a command's output
today="$(date +%F)"
echo "today is $today"
# -> today is 2026-10-08

# Default values and required values
port="${PORT:-8080}"      # use $PORT, or 8080 if unset/empty
file="${1:?usage: backup.sh FILE}"   # error out if $1 is missing
Common mistake: unquoted variables. rm -rf $dir/* with $dir empty becomes rm -rf /* — catastrophic. Quoting ("$dir") and set -u (error on unset variables) together prevent the whole class. Treat every $var as if it might contain spaces or be empty, because one day it will.

Conditionals: if and [[ ]]

Intermediate Use [[ ... ]] (bash's test construct) over the older [ ... ] — it is safer with unquoted variables and supports &&, ||, and pattern matching.

if [[ -f "$file" ]]; then
  echo "$file exists"
elif [[ -d "$file" ]]; then
  echo "$file is a directory"
else
  echo "$file not found"
fi

# Numeric vs string comparison
count=5
[[ $count -gt 3 ]] && echo "more than three"      # -gt -lt -eq -ge for numbers
[[ "$env" == prod ]] && echo "production"          # == != for strings
[[ "$name" == A* ]] && echo "starts with A"        # glob pattern match
TestTrue when
-f pathpath is a regular file.
-d pathpath is a directory.
-e pathpath exists (any type).
-z str / -n strstring is empty / non-empty.
a -gt bnumber a greater than b (-lt -eq -ge -le -ne too).

Loops

# for over a list / glob (quote the loop variable!)
for f in /var/log/*.log; do
  echo "rotating $f"
done

# C-style for with a counter
for ((i=1; i<=3; i++)); do echo "attempt $i"; done
# -> attempt 1 / attempt 2 / attempt 3

# while, reading a file line by line (the safe idiom)
while IFS= read -r line; do
  echo "got: $line"
done < input.txt

# until: loop until a condition becomes true (e.g. wait for a service)
until curl -sf http://localhost:8080/health >/dev/null; do
  echo "waiting for app..."; sleep 1
done

Functions, arguments, and exit codes

Intermediate Positional arguments are $1, $2, …; $@ is all of them, $# is the count. Every command returns an exit code: 0 means success, non-zero means failure — this is what if and && actually test.

log() { echo "[$(date +%T)] $*"; }     # $* / $@ = all args

greet() {
  local who="${1:-world}"              # 'local' keeps it scoped to the function
  echo "hello, $who"
  return 0                             # explicit exit code
}

greet Ada
# -> hello, Ada
log "starting with $# args: $@"

# Exit codes drive control flow
if grep -q ERROR app.log; then
  log "errors found"; exit 1           # non-zero = this script failed
fi
echo "last command exit code: $?"      # $? holds the previous exit code

set -euo pipefail: the safety line

Intermediate Put this near the top of every non-trivial script. It converts the three silent-failure traps that bite everyone into immediate, visible errors.

OptionEffect
set -eExit immediately if any command fails (non-zero), instead of plowing on.
set -uError on use of an unset variable — catches typos and empty paths.
set -o pipefailA pipeline fails if any stage fails, not just the last — false | true now fails.
 
#!/usr/bin/env bash
set -euo pipefail
IFS=$'\n\t'                 # safer word-splitting (newlines/tabs only, not spaces)

# With -e, this script stops the moment tar fails — you never run the next line
# against a half-made archive. Without it, failures pass silently.
trap 'echo "FAILED at line $LINENO" >&2' ERR   # print where it died
Even with set -e, a command whose failure you expect (like grep finding nothing) will abort the script. Guard those explicitly: grep X file || true, or test in an if. And remember set -e does not fire inside &&/|| chains or on the left of a pipe without pipefail — which is exactly why you want all three options together.

Exercises

  • Write a script that takes a filename as $1, errors with a usage message if none is given (${1:?...}), and prints whether it exists.
  • Loop over every .txt file in a directory and print its line count, quoting the loop variable correctly.
  • Write a function that retries a command up to 3 times with a 2-second sleep between attempts, returning the command's exit code.
  • Add set -euo pipefail and an ERR trap to a script, then deliberately reference an unset variable and watch it fail loudly with the line number.

Mini-project: a real backup script

Write a production-shaped backup script: strict mode, argument validation, logging, a retention policy, and a clear success/failure exit code — everything a cron job or systemd timer would invoke.

#!/usr/bin/env bash
set -euo pipefail
IFS=$'\n\t'

# --- config (overridable via environment) ---
SRC="${1:?usage: backup.sh SOURCE_DIR [DEST_DIR]}"
DEST="${2:-/var/backups}"
KEEP_DAYS="${KEEP_DAYS:-7}"
STAMP="$(date +%Y%m%d-%H%M%S)"
ARCHIVE="$DEST/$(basename "$SRC")-$STAMP.tar.gz"

log()  { echo "[$(date +%T)] $*"; }
die()  { echo "[$(date +%T)] ERROR: $*" >&2; exit 1; }
trap 'die "aborted at line $LINENO"' ERR

# --- preconditions ---
[[ -d "$SRC" ]]  || die "source '$SRC' is not a directory"
mkdir -p "$DEST"

# --- do the work ---
log "backing up $SRC -> $ARCHIVE"
tar czf "$ARCHIVE" -C "$(dirname "$SRC")" "$(basename "$SRC")"
size="$(du -h "$ARCHIVE" | cut -f1)"
log "created $ARCHIVE ($size)"

# --- retention ---
deleted="$(find "$DEST" -name '*.tar.gz' -mtime +"$KEEP_DAYS" -print -delete | wc -l)"
log "pruned $deleted archive(s) older than $KEEP_DAYS days"
log "backup OK"
./backup.sh /var/www/site
# -> [10:40:02] backing up /var/www/site -> /var/backups/site-20261008-104002.tar.gz
# -> [10:40:03] created /var/backups/site-20261008-104002.tar.gz (4.1M)
# -> [10:40:03] pruned 1 archive(s) older than 7 days
# -> [10:40:03] backup OK
echo $?
# -> 0        (success — a monitoring tool or cron can rely on this)

Run it with a missing argument and it exits non-zero with a usage message; run it against a bad path and the ERR trap reports the exact line. That combination of strict mode, validation, logging, and a meaningful exit code is what separates a throwaway snippet from a script you can schedule and forget.
