The Unix philosophy is small tools piped together. grep finds lines, sed edits streams, awk processes fields, and sort/uniq/cut/tr reshape data. Chain them and you can slice any log or data file without writing a program.

grep — find lines

grep "ERROR" app.log                 # lines containing ERROR
grep -i "error" app.log              # case-insensitive
grep -r "TODO" ./src                 # recursive through a tree
grep -n "func main" main.go          # show line numbers
grep -c "GET" access.log             # count matching lines
grep -v "healthcheck" access.log     # INVERT: lines NOT matching
grep -E "4[0-9]{2}|5[0-9]{2}" access.log   # extended regex: 4xx/5xx
grep -A2 -B2 "panic" app.log         # 2 lines of context After/Before
grep -o prints only the matching part (not the whole line) — great for extracting fields: grep -oE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' access.log pulls every IP.

sed — stream editing

Intermediate sed transforms text as it flows past — substitutions, deletions, insertions:

sed 's/foo/bar/' file          # replace FIRST foo per line
sed 's/foo/bar/g' file         # replace ALL (global)
sed 's/foo/bar/gi' file        # all, case-insensitive
sed -n '10,20p' file           # print only lines 10–20 (-n = quiet)
sed '/^#/d' config             # delete comment lines
sed '/^$/d' file               # delete blank lines
sed -i 's/8080/9090/g' app.conf  # edit the file IN PLACE
Common mistake: sed -i with no backup on a file you can't easily regenerate — it overwrites irreversibly. Test the substitution without -i first (watch stdout), then use sed -i.bak to keep a .bak copy. Also mind the delimiter: substituting paths with / is cleaner as sed 's#/old/path#/new/path#'.

awk — field processing

Intermediate awk splits each line into fields ($1, $2, … $NF = last) and runs a little program per line. It's a calculator for columns.

# Print the 1st and 3rd whitespace-separated columns
awk '{print $1, $3}' data.txt

# Sum column 2
awk '{sum += $2} END {print sum}' sales.txt

# Average response time from an access log (field 10)
awk '{t += $10; n++} END {printf "avg %.1fms\n", t/n}' access.log

# Filter: rows where column 3 > 100
awk '$3 > 100' data.txt

# Custom field separator (CSV) + a header
awk -F, 'NR>1 {print $2}' data.csv       # skip header (NR = row number)

# Count occurrences of each status code (field 9)
awk '{count[$9]++} END {for (c in count) print c, count[c]}' access.log

sort, uniq, cut, tr

sort file                      # alphabetical
sort -n file                   # numeric
sort -rn -k2 file              # reverse-numeric by column 2
sort file | uniq               # dedupe (uniq needs sorted input!)
sort file | uniq -c | sort -rn # count + rank by frequency
cut -d, -f1,3 data.csv         # columns 1 and 3 of a CSV
cut -c1-10 file                # first 10 characters
tr 'a-z' 'A-Z' < file          # uppercase
tr -d ' ' < file               # delete spaces
Classic gotcha: uniq only collapses adjacent duplicates, so uniq on unsorted input misses most of them. The idiom is always sort | uniq (or sort -u). The "top-N" one-liner sort | uniq -c | sort -rn | head is worth memorizing.

Putting it together

# Top 10 IPs hitting your server with 5xx errors
grep -E ' 5[0-9]{2} ' access.log \
  | awk '{print $1}' \
  | sort | uniq -c | sort -rn \
  | head -10

Exercises

  • From an access log, extract the top 10 most-requested URLs with a grep|awk|sort|uniq pipeline.
  • Use sed to change a port number across a config file (test without -i first).
  • With awk, compute the average of a numeric column and the count per category.

Mini-project: a log-analysis one-liner toolkit

Given a web access log, build a small set of pipelines: requests-per-hour histogram (awk on the timestamp + uniq -c), top error-producing endpoints, slowest average endpoints, and unique visitor count. Save them as shell functions (tying into the Bash Scripting lesson) so you have a reusable log-triage kit — the kind of thing you reach for during an incident.
