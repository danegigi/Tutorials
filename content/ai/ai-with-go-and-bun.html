Go and Bun are both excellent languages for building AI-powered services: Go for high-throughput API backends and Bun for fast TypeScript serverless and full-stack apps. This lesson covers calling LLM APIs, streaming responses, function calling, building agents, and using the Go (Eino) and Bun (Vercel AI SDK) frameworks — basic through advanced, with production patterns for cost, latency, and error handling.

Why Go and Bun for AI

Beginner Python dominates AI research, but production AI services have different priorities:

NeedGoBun
High-concurrency API gateways✓ Goroutines are built for this✓ Bun.serve() is fast
Low latency, minimal overhead✓ Compiled, no GC pauses in hot paths✓ V8-based, no cold start
Streaming responses (SSE)✓ net/http handles it natively✓ ResponseStream + AI SDK
Type safety✓ Static types✓ TypeScript
Existing infra integration✓ Already in your stack✓ Full-stack monorepos

The AI model is a remote API call. Your language choice is about how you wrap that call — error handling, streaming, rate limiting, caching — and both Go and Bun are better at that than a Python script.

Calling an LLM API: the fundamentals

Beginner Every LLM API is the same shape: send a prompt, get a completion. Here's the raw call in both languages.

Go with the official SDKs

// go get github.com/anthropics/anthropic-sdk-go
// go get github.com/openai/openai-go

package main

import (
    "context"
    "fmt"
    "github.com/anthropics/anthropic-sdk-go"
    "github.com/anthropics/anthropic-sdk-go/option"
)

func main() {
    client := anthropic.NewClient(option.WithAPIKey(""))  // reads ANTHROPIC_API_KEY

    resp, err := client.Messages.New(context.Background(), anthropic.MessageNewParams{
        Model:     anthropic.F("claude-sonnet-4-5"),
        MaxTokens: anthropic.F(int64(1024)),
        Messages: anthropic.F([]anthropic.MessageParam{
            anthropic.NewUserMessage(anthropic.NewTextBlock("Explain goroutines in one sentence.")),
        }),
    })
    if err != nil {
        panic(err)
    }
    fmt.Println(resp.Content[0].Text)
    // "A goroutine is a lightweight thread of execution managed by the Go runtime..."
}

Streaming responses

Beginner Streaming lets the user see tokens as they're generated instead of waiting for the full response. This is critical for chat UIs — perceived latency drops from 3 seconds to 200ms.

Go: SSE streaming

// stream.go — streaming a Claude response over HTTP
package main

import (
    "context"
    "encoding/json"
    "fmt"
    "net/http"
    "github.com/anthropics/anthropic-sdk-go"
    "github.com/anthropics/anthropic-sdk-go/option"
)

func streamHandler(w http.ResponseWriter, r *http.Request) {
    // SSE headers
    w.Header().Set("Content-Type", "text/event-stream")
    w.Header().Set("Cache-Control", "no-cache")
    w.Header().Set("Connection", "keep-alive")

    client := anthropic.NewClient()
    stream := client.Messages.NewStreaming(context.Background(), anthropic.MessageNewParams{
        Model:     anthropic.F("claude-sonnet-4-5"),
        MaxTokens: anthropic.F(int64(1024)),
        Messages: anthropic.F([]anthropic.MessageParam{
            anthropic.NewUserMessage(anthropic.NewTextBlock("Write a haiku about Go.")),
        }),
    })

    for stream.Next() {
        event := stream.Current()
        if event.Delta != nil {
            // Send each text delta as an SSE event
            data, _ := json.Marshal(map[string]string{
                "text": event.Delta.Text,
            })
            fmt.Fprintf(w, "data: %s\n\n", data)
            w.(http.Flusher).Flush()
        }
    }
    if err := stream.Err(); err != nil {
        fmt.Fprintf(w, "data: {\"error\": \"%s\"}\n\n", err.Error())
    }
    fmt.Fprintf(w, "data: [DONE]\n\n")
}

func main() {
    http.HandleFunc("/stream", streamHandler)
    http.ListenAndServe(":8080", nil)
}

Bun.serve({

    const { prompt } = await req.json();

    const response = await fetch("https://api.anthropic.com/v1/messages", {
      method: "POST",
      headers: {
        "x-api-key": Bun.env.ANTHROPIC_API_KEY!,
        "anthropic-version": "2023-06-01",
        "content-type": "application/json",
      },
      body: JSON.stringify({
        model: "claude-sonnet-4-5",
        max_tokens: 1024,
        stream: true,  // enables streaming
        messages: [{ role: "user", content: prompt }],

    return new Response(response.body, {
      headers: { "content-type": "text/event-stream" },
    });
  },
});
Bun streams a fetch Response body directly to the HTTP response with zero copying. This makes it trivial to build a streaming proxy — receive from the LLM API, pipe to the client, no buffering. Go needs manual Flush() calls but gives you more control over each event.

Function calling (tool use)

Intermediate Function calling lets the model request that your code run a function it can't do itself — query a database, call an API, read a file — and feed the result back. This is how you build agents in Go and Bun.

Go: function calling with the Anthropic SDK

// agent.go — a Go agent that can call tools
package main

import (
    "context"
    "encoding/json"
    "fmt"
    "github.com/anthropics/anthropic-sdk-go"
    "github.com/anthropics/anthropic-sdk-go/option"
)

type Tool struct {
    Name        string
    Description string
    InputSchema map[string]any
    Handler     func(params map[string]any) (string, error)
}

func main() {
    client := anthropic.NewClient()

    // Define tools the model can call
    tools := map[string]Tool{
        "get_weather": {
            Name:        "get_weather",
            Description: "Get the current weather for a city",
            InputSchema: map[string]any{
                "type": "object",
                "properties": map[string]any{
                    "city": map[string]any{
                        "type":        "string",
                        "description": "The city name",
                    },
                },
                "required": []string{"city"},
            },
            Handler: func(params map[string]any) (string, error) {
                city := params["city"].(string)
                // In reality: call a weather API
                return fmt.Sprintf("It's 72°F and sunny in %s", city), nil
            },
        },
    }

    // The agent loop
    messages := []anthropic.MessageParam{
        anthropic.NewUserMessage(anthropic.NewTextBlock("What's the weather in Tokyo?")),
    }

    for {
        resp, err := client.Messages.New(context.Background(), anthropic.MessageNewParams{
            Model:     anthropic.F("claude-sonnet-4-5"),
            MaxTokens: anthropic.F(int64(1024)),
            Messages:  anthropic.F(messages),
            Tools: anthropic.F([]anthropic.ToolParam{
                {
                    Name:        anthropic.F("get_weather"),
                    Description: anthropic.F("Get the current weather for a city"),
                    InputSchema: anthropic.F(tools["get_weather"].InputSchema),
                },
            }),
        })
        if err != nil {
            panic(err)
        }

        // Check if the model wants to call a tool
        if resp.StopReason == "tool_use" {
            for _, block := range resp.Content {
                if block.Type == "tool_use" {
                    tool := tools[block.Name]
                    result, err := tool.Handler(block.Input)
                    if err != nil {
                        result = fmt.Sprintf("Error: %v", err)
                    }

                    // Feed the tool result back to the model
                    messages = append(messages,
                        anthropic.NewAssistantMessage(resp.Content...),
                        anthropic.NewUserMessage(anthropic.NewToolResultBlock(block.ID, result, false)),
                    )
                }
            }
            continue  // loop back to let the model process the result
        }

        // No tool call — the model is done
        fmt.Println(resp.Content[0].Text)
        break
    }
}

Bun: function calling with the AI SDK

// bun add ai @ai-sdk/anthropic zod

import { streamText, tool } from "ai";
import Anthropic from "@ai-sdk/anthropic";
import { z } from "zod";

Bun.serve({
  port: 3000,
  async fetch(req) {
    const { messages } = await req.json();

    const result = streamText({
      model: Anthropic("claude-sonnet-4-5"),
      messages,
      maxSteps: 5,  // allow up to 5 tool-call rounds
      tools: {
        get_weather: tool({
          description: "Get the current weather for a city",
          parameters: z.object({
            city: z.string().describe("The city name"),
          }),
          execute: async ({ city }) => {
            // In reality: call a weather API
            return `It's 72°F and sunny in ${city}`;
          },
        }),
        query_db: tool({
          description: "Run a read-only SQL query on the database",
          parameters: z.object({
            sql: z.string().describe("SELECT query"),
          }),
          execute: async ({ sql }) => {
            const db = require("bun:sqlite").default(":memory:");
            const rows = db.query(sql).all();
            return JSON.stringify(rows);
          },
        }),
      },
    });

    return result.toDataStreamResponse();
  },
});
The AI SDK's maxSteps: 5 handles the agent loop for you — the model calls a tool, the result goes back, the model decides whether to call another tool or answer. In Go, you write this loop manually (as shown above), which gives you more control but is more code.

Eino: composable pipelines

// Build a RAG pipeline with Eino's graph API
import (
    "github.com/cloudwego/eino"
    "github.com/cloudwego/eino/components/retriever"
    "github.com/cloudwego/eino/components/prompt"
)

func buildRAGPipeline(ctx context.Context) {
    // Define nodes in a graph
    g := graph.New()

    // Node 1: format the prompt with retrieved context
    g.AddLambdaNode("prompt_builder", func(ctx context.Context, input map[string]any) (map[string]any, error) {
        query := input["query"].(string)
        context := input["retrieved_docs"].([]string)
        prompt := fmt.Sprintf("Context:\n%s\n\nQuestion: %s\n\nAnswer:", join(context), query)
        return map[string]any{"prompt": prompt}, nil
    })

    // Node 2: call the LLM
    g.AddChatModelNode("llm", chatModel)

    // Connect: retriever → prompt_builder → llm
    g.AddEdge("retriever", "prompt_builder")
    g.AddEdge("prompt_builder", "llm")

    // Run the pipeline
    result, err := g.Invoke(ctx, map[string]any{"query": "How do I configure pgvector?"})
}

Bun frameworks: the Vercel AI SDK

Production patterns

Advanced

Rate limiting and retry

// Bun: exponential backoff with jitter
async function callWithRetry(fn: () => Promise<Response>, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      const res = await fn();
      if (res.status === 429) {
        // Rate limited — get retry-after header
        const retryAfter = parseInt(res.headers.get("retry-after") || "5");
        const jitter = Math.random() * 1000;  // 0-1s jitter
        await Bun.sleep((retryAfter * 1000) + jitter);
        continue;
      }
      return res;
    } catch (err) {
      if (attempt === maxRetries - 1) throw err;
      const delay = Math.pow(2, attempt) * 1000 + Math.random() * 500;
      await Bun.sleep(delay);
    }
  }
  throw new Error("Max retries exceeded");
}

Cost tracking and budgeting

// Go: track token usage per request
type UsageTracker struct {
    mu        sync.Mutex
    totalIn   int64
    totalOut  int64
    costPerM  float64  // cost per 1M tokens
}

func (t *UsageTracker) Record(usage anthropic.Usage) {
    t.mu.Lock()
    defer t.mu.Unlock()
    t.totalIn += usage.InputTokens
    t.totalOut += usage.OutputTokens
}

func (t *UsageTracker) Cost() float64 {
    return (float64(t.totalIn)+float64(t.totalOut)) * t.costPerM / 1_000_000
}

// Per-request budget guard
func callWithBudget(client *anthropic.Client, msg anthropic.MessageNewParams, maxTokens int64) (*anthropic.Message, error) {
    if msg.MaxTokens.Value > maxTokens {
        return nil, fmt.Errorf("requested %d tokens exceeds budget %d", msg.MaxTokens.Value, maxTokens)
    }
    resp, err := client.Messages.New(context.Background(), msg)
    if err != nil {
        return nil, err
    }
    tracker.Record(resp.Usage)
    if tracker.Cost() > monthlyBudget {
        return nil, errors.New("monthly budget exceeded")
    }
    return resp, nil
}

// Bun: use AbortSignal for the same effect
const controller = new AbortController();
const timeout = setTimeout(() => controller.abort(), 30_000);

try {
  const res = await fetch(url, { ..., signal: controller.signal });
} catch (err) {
  if (err.name === "AbortError") {
    throw new Error("LLM call timed out after 30s");
  }
  throw err;
} finally {
  clearTimeout(timeout);
}

Caching common responses

// Bun: cache by prompt hash to avoid redundant API calls
import { createHash } from "crypto";

const cache = new Map<string, string>();

async function cachedGenerate(prompt: string, model: string) {
  const key = createHash("sha256").update(`${model}:${prompt}`).digest("hex");

  if (cache.has(key)) {
    return cache.get(key)!;  // cache hit — no API call
  }

  const result = await generateText({ model, prompt });
  cache.set(key, result.text);
  return result.text;
}

Polyglot pattern: Go backend + Bun frontend

Advanced A common architecture: Go handles the heavy API gateway (auth, rate limiting, database), and Bun serves the streaming chat frontend that calls through to Go:

// Go: the AI gateway (port 8080)
// Handles auth, rate limiting, budget tracking, and proxies to the LLM API
func aiGateway(w http.ResponseWriter, r *http.Request) {
    user := authMiddleware(r)
    if !user.HasQuota() {
        http.Error(w, "quota exceeded", http.StatusPaymentRequired)
        return
    }

    // Proxy the streaming response from the LLM API to the client
    resp, err := http.Post("https://api.anthropic.com/v1/messages", "application/json", r.Body)
    if err != nil {
        http.Error(w, err.Error(), 502)
        return
    }
    defer resp.Body.Close()

    // Track usage
    usage := parseUsage(resp.Header)
    tracker.Record(user.ID, usage)

    // Stream to client
    io.Copy(w, resp.Body)
}

// Bun: the frontend chat server (port 3000)
// Serves the UI and proxies chat requests to the Go gateway
Bun.serve({
  port: 3000,
  async fetch(req) {
    if (req.url.startsWith("/api/chat")) {
      return fetch("http://localhost:8080/ai", {
        method: "POST",
        headers: { ...req.headers, "Authorization": `Bearer ${sessionToken}` },
        body: await req.text(),
      });
    }
    return new Response(Bun.file("chat.html"));
  },
});
This split gives you the best of both: Go's type safety and performance for the API layer, Bun's streaming and TypeScript for the frontend. The LLM API call happens in Go (with budget tracking, rate limiting), and the stream flows through Bun to the browser.

Common mistakes

  • No timeout on LLM calls. An LLM API can hang for minutes. Always set a context timeout (Go) or AbortSignal (Bun) — 30 seconds is a reasonable default.
  • Not streaming. Waiting for a full 3-second response when you could stream the first token in 200ms feels broken. Always stream for user-facing chat.
  • No retry on 429. LLM APIs rate-limit aggressively. Implement exponential backoff with jitter and respect the retry-after header.
  • Not tracking cost. LLM APIs charge per token. Without usage tracking, you won't notice a runaway loop until the bill arrives. Log input + output tokens per request.
  • Exposing the API key to the client. Never call the LLM API directly from the browser. Route through your backend so the key stays server-side.
  • Using LangChainGo in new projects. It's effectively unmaintained. Use Eino for new Go projects, or call the SDK directly — the Anthropic and OpenAI Go SDKs are well-maintained.
  • Not caching. Repeated identical prompts (FAQs, common queries) can be cached by prompt hash. This can cut API costs dramatically for high-traffic services.
