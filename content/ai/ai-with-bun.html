Bun is a fast TypeScript runtime that's excellent for building AI-powered apps: zero-dependency fetch() for API calls, Bun.serve() for streaming endpoints, and native support for the Vercel AI SDK. This lesson covers calling LLM APIs, streaming with the AI SDK and raw fetch, function calling, structured output, multi-provider routing, retry and caching patterns, and the polyglot Go-backend + Bun-frontend architecture — basic through advanced.

Calling an LLM API: the fundamentals

Beginner Every LLM API is the same shape: send a prompt, get a completion. Bun's built-in fetch() is all you need — no SDK required for basic calls:

// No dependency needed — just fetch()
const resp = await fetch("https://api.anthropic.com/v1/messages", {
  method: "POST",
  headers: {
    "x-api-key": Bun.env.ANTHROPIC_API_KEY!,
    "anthropic-version": "2023-06-01",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "claude-sonnet-4-5",
    max_tokens: 1024,
    messages: [{ role: "user", content: "Explain goroutines in one sentence." }],
  }),
});

const data = await resp.json();
console.log(data.content[0].text);
// "A goroutine is a lightweight thread of execution managed by the Go runtime..."

OpenAI API with fetch

const resp = await fetch("https://api.openai.com/v1/chat/completions", {

For simple one-off calls, raw fetch() is all you need. Reach for the Vercel AI SDK (covered below) when you want streaming, function calling, structured output, or multi-provider routing — it wraps all of that with clean TypeScript types.

Streaming responses

Beginner Streaming lets the user see tokens as they're generated instead of waiting for the full response. This is critical for chat UIs — perceived latency drops from 3 seconds to 200ms.

With the Vercel AI SDK

// bun add ai @ai-sdk/anthropic

import { AnthropicStream } from "ai";
import Anthropic from "@ai-sdk/anthropic";

Bun.serve({
  port: 3000,
  async fetch(req) {
    const { messages } = await req.json();
    const result = await AnthropicStream({
      model: Anthropic("claude-sonnet-4-5"),
      messages,
      max_tokens: 1024,
    });
    return result.toDataStreamResponse();  // returns a streaming Response
  },
});

Raw streaming without any SDK

Bun can pipe a fetch Response body directly to the HTTP response with zero copying. This makes it trivial to build a streaming proxy — receive from the LLM API, pipe to the client, no buffering:

// No dependencies — pure fetch streaming
Bun.serve({
  port: 3000,
  async fetch(req) {
    const { prompt } = await req.json();

    const response = await fetch("https://api.anthropic.com/v1/messages", {
      method: "POST",
      headers: {
        "x-api-key": Bun.env.ANTHROPIC_API_KEY!,
        "anthropic-version": "2023-06-01",
        "content-type": "application/json",
      },
      body: JSON.stringify({
        model: "claude-sonnet-4-5",
        max_tokens: 1024,
        stream: true,  // enables streaming from the API
        messages: [{ role: "user", content: prompt }],
      }),
    });

    // Pipe the SSE stream directly to the client — zero copying in Bun
    return new Response(response.body, {
      headers: { "content-type": "text/event-stream" },
    });
  },
});
Bun streams a fetch Response body directly to the HTTP response with zero copying — you receive from the LLM API and pipe to the client in one line. This is Bun's key advantage for streaming proxies: no buffering, no intermediate streams, no manual flushing.

Function calling with the AI SDK

Intermediate Function calling lets the model request that your code run a function it can't do itself — query a database, call an API, read a file — and feed the result back. The Vercel AI SDK handles the agent loop for you with maxSteps:

// bun add ai @ai-sdk/anthropic zod

import { streamText, tool } from "ai";
import Anthropic from "@ai-sdk/anthropic";
import { z } from "zod";

Bun.serve({
  port: 3000,
  async fetch(req) {
    const { messages } = await req.json();

    const result = streamText({
      model: Anthropic("claude-sonnet-4-5"),
      messages,
      maxSteps: 5,  // allow up to 5 tool-call rounds
      tools: {
        get_weather: tool({
          description: "Get the current weather for a city",
          parameters: z.object({
            city: z.string().describe("The city name"),
          }),
          execute: async ({ city }) => {
            // In reality: call a weather API
            return `It's 72°F and sunny in ${city}`;
          },
        }),
        query_db: tool({
          description: "Run a read-only SQL query on the database",
          parameters: z.object({
            sql: z.string().describe("SELECT query"),
          }),
          execute: async ({ sql }) => {
            const db = require("bun:sqlite").default(":memory:");
            const rows = db.query(sql).all();
            return JSON.stringify(rows);
          },
        }),
      },
    });

    return result.toDataStreamResponse();
  },
});
The AI SDK's maxSteps: 5 handles the agent loop for you — the model calls a tool, the result goes back, the model decides whether to call another tool or answer. In Go (see the AI with Go lesson), you write this loop manually, which gives more control but is more code. Bun + AI SDK is faster to build; Go is more explicit.

The Vercel AI SDK: beyond basics

Intermediate The Vercel AI SDK is the dominant TypeScript AI library and runs natively under Bun. It abstracts streaming, tool use, structured output, and multi-provider switching:

Multi-provider switching

// bun add ai @ai-sdk/anthropic @ai-sdk/openai zod

import { generateText, streamText, generateObject, tool } from "ai";
import Anthropic from "@ai-sdk/anthropic";
import OpenAI from "@ai-sdk/openai";
import { z } from "zod";

// Switch models with one line
const claude = Anthropic("claude-sonnet-4-5");
const gpt = OpenAI("gpt-4o");

// Simple generation
const { text } = await generateText({
  model: claude,
  prompt: "Write a Go HTTP handler for health checks.",
});
console.log(text);

Structured output (enforced schema)

// generateObject enforces a Zod schema — the model must return valid JSON
const { object } = await generateObject({
  model: claude,
  schema: z.object({
    title: z.string(),
    severity: z.enum(["critical", "moderate", "minor"]),
    description: z.string(),
    fix: z.string(),
  }),
  prompt: "Review this Go function for bugs:\n\nfunc divide(a, b float64) float64 { return a / b }",
});
// { title: "Division by zero", severity: "critical", description: "...", fix: "..." }

Multi-provider routing (cost optimization)

// Use cheap model for simple tasks, powerful model for complex ones
async function smartGenerate(prompt: string) {
  const model = prompt.length < 200
    ? Anthropic("claude-haiku-4-5")   // cheap, fast
    : Anthropic("claude-sonnet-4-5"); // powerful, more expensive
  return generateText({ model, prompt });
}
Multi-provider routing is a practical cost saver: route short, simple prompts to a cheap model (Haiku) and complex prompts to a powerful one (Sonnet). The AI SDK makes this a one-line change — no code restructuring needed.

Rate limiting and retry with backoff

// Exponential backoff with jitter
async function callWithRetry(fn: () => Promise<Response>, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      const res = await fn();
      if (res.status === 429) {
        // Rate limited — get retry-after header
        const retryAfter = parseInt(res.headers.get("retry-after") || "5");
        const jitter = Math.random() * 1000;  // 0-1s jitter
        await Bun.sleep((retryAfter * 1000) + jitter);
        continue;
      }
      return res;
    } catch (err) {
      if (attempt === maxRetries - 1) throw err;
      const delay = Math.pow(2, attempt) * 1000 + Math.random() * 500;
      await Bun.sleep(delay);
    }
  }
  throw new Error("Max retries exceeded");
}

Timeouts with AbortSignal

// Always set a timeout — an LLM API can hang for minutes
const controller = new AbortController();
const timeout = setTimeout(() => controller.abort(), 30_000);  // 30s

try {
  const res = await fetch("https://api.anthropic.com/v1/messages", {
    method: "POST",
    headers: {
      "x-api-key": Bun.env.ANTHROPIC_API_KEY!,
      "anthropic-version": "2023-06-01",
      "content-type": "application/json",
    },
    body: JSON.stringify({
      model: "claude-sonnet-4-5",
      max_tokens: 1024,
      messages: [{ role: "user", content: prompt }],
    }),
    signal: controller.signal,  // abort after 30s
  });
  const data = await res.json();
  return data.content[0].text;
} catch (err) {
  if (err.name === "AbortError") {
    throw new Error("LLM call timed out after 30s");
  }
  throw err;
} finally {
  clearTimeout(timeout);
}

Caching common responses

// Cache by prompt hash to avoid redundant API calls
import { createHash } from "crypto";

const cache = new Map<string, string>();

async function cachedGenerate(prompt: string, model: string) {
  const key = createHash("sha256").update(`${model}:${prompt}`).digest("hex");

  if (cache.has(key)) {
    return cache.get(key)!;  // cache hit — no API call
  }

  const result = await generateText({ model, prompt });
  cache.set(key, result.text);
  return result.text;
}

// For distributed cache: use Redis instead of Map
// const cached = await redis.get(key);
// if (cached) return cached;
Caching by prompt hash only works for deterministic prompts. If your prompt includes timestamps, random IDs, or user-specific context, the hash changes every time and the cache never hits. Strip variable parts before hashing, or cache at a higher level (e.g. "review this file" keyed by file content hash, not the full prompt).

Polyglot pattern: Go backend + Bun frontend

Advanced A common production architecture: Go handles the heavy API gateway (auth, rate limiting, budget tracking, database), and Bun serves the streaming chat frontend that calls through to Go. This gives you the best of both: Go's type safety and performance for the API layer, Bun's streaming and TypeScript for the frontend.

Common mistakes

  • No timeout on LLM calls. An LLM API can hang for minutes. Always use AbortSignal — 30 seconds is a reasonable default.
  • Not streaming. Waiting for a full 3-second response when you could stream the first token in 200ms feels broken. Always stream for user-facing chat.
  • No retry on 429. LLM APIs rate-limit aggressively. Implement exponential backoff with jitter and respect the retry-after header.
  • Not tracking cost. LLM APIs charge per token. Without usage tracking, you won't notice a runaway loop until the bill arrives. Log input + output tokens per request.
  • Exposing the API key to the client. Never call the LLM API directly from the browser. Route through your backend (Bun or Go) so the key stays server-side.
  • Not caching. Repeated identical prompts (FAQs, common queries) can be cached by prompt hash. This can cut API costs dramatically for high-traffic services.
  • Caching non-deterministic prompts. If your prompt includes timestamps or random IDs, the cache never hits. Strip variable parts before hashing.
