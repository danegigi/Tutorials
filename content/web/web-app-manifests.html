The web app manifest is a JSON file that tells the browser how to present your app when installed: its name, icons, colors, launch URL, and display mode. It's small, but every field changes the installed experience.

A complete manifest

// manifest.webmanifest  (served as application/manifest+json)
{
  "name": "Dev Tutorials",
  "short_name": "Tutorials",
  "description": "Offline-ready tutorials for Go, Bun, Web, Linux, DevOps.",
  "start_url": "./index.html",
  "scope": "./",
  "display": "standalone",
  "orientation": "any",
  "background_color": "#0d1117",
  "theme_color": "#0d1117",
  "icons": [
    { "src": "icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "icon-512.png", "sizes": "512x512", "type": "image/png" },
    { "src": "icon-maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ],
  "shortcuts": [
    { "name": "Golang", "url": "./golang/index.html" },
    { "name": "DevOps", "url": "./devops/index.html" }
  ]
}

This is the actual manifest for this tutorial (trimmed). Link it from every page: <link rel="manifest" href="/manifest.webmanifest">.

What each field controls

FieldEffect
nameFull name on the install dialog and splash screen.
short_nameLabel under the home-screen icon (keep ≤12 chars).
start_urlWhat opens when the icon is tapped. Add ?source=pwa to measure installs.
scopeURLs that stay "in" the app; outside links open a browser.
displaystandalone (no browser UI), fullscreen, minimal-ui, or browser.
theme_colorToolbar/status-bar color of the installed app.
background_colorSplash-screen background while the app loads.
iconsHome-screen/launcher icons at required sizes.
shortcutsLong-press jump actions on the installed icon.

Icons: sizes and maskable

Intermediate You need at least 192×192 and 512×512 PNGs. An SVG with "sizes": "any" is a nice extra. Then there's the maskable purpose:

{ "src": "icon-maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
Maskable icons let Android crop your icon into circles, squircles, and rounded squares without clipping content. Keep the important part inside the central 80% "safe zone" and fill the whole canvas (no transparency around the edges) — a normal icon used as maskable gets its corners chopped off. Test designs at maskable.app.

Display modes

ModeLooks like
standaloneOwn window, app icon, no address bar — the usual choice.
fullscreenNo system UI at all — games, kiosks.
minimal-uiStandalone + minimal back/reload controls.
browserA normal tab (not really "installed").

Validating

# DevTools → Application → Manifest shows parsed fields + icon previews
#   and lists installability errors ("no matching icon", bad start_url, etc.)
Common mistakes: (1) wrong MIME type — serve .webmanifest as application/manifest+json or some browsers ignore it. (2) start_url outside scope — install silently fails. (3) relative paths that resolve wrong depending on which page linked the manifest; use paths relative to the manifest's own location or absolute from root.

Exercises

  • Write a manifest with name, two icon sizes, start_url, and display: standalone; verify in the DevTools Manifest panel.
  • Add a maskable icon and confirm (in the panel's preview) nothing important is clipped.
  • Add two shortcuts and long-press the installed icon to use them.

Mini-project: a themed installable app

Author a manifest for an app of yours with a matching theme_color/background_color, a proper icon set including a maskable variant, and 2–3 shortcuts to key routes. Install it on desktop and (if possible) a phone, and confirm the splash screen, window chrome color, and icon all look right.
