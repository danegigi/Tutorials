Performance is a feature users feel. Google's Core Web Vitals turn "fast" into three measurable numbers — LCP, CLS, and INP — that are also ranking signals. Learn what each measures, how to diagnose a bad score, and the concrete fixes.

The three Core Web Vitals

MetricMeasuresGoodPoor
LCP (Largest Contentful Paint)Time until the biggest element renders≤ 2.5s> 4s
CLS (Cumulative Layout Shift)How much the layout jumps around≤ 0.1> 0.25
INP (Interaction to Next Paint)Responsiveness to taps/clicks≤ 200ms> 500ms

Beginner LCP is loading, CLS is visual stability, INP is interactivity — loading, looking, and responding. Lighthouse measures them in a lab; real-user data (CrUX / the web-vitals library) measures them in the field.

Fixing LCP

<!-- Preload the LCP image / hero so it starts downloading immediately -->
<link rel="preload" as="image" href="/hero.webp" fetchpriority="high">

<!-- Serve modern formats + right size (see Responsive Design) -->
<img src="hero.webp" width="1200" height="630" fetchpriority="high" alt="…">
  • Compress and right-size images (usually the LCP element); serve AVIF/WebP.
  • Eliminate render-blocking CSS/JS; inline critical CSS, defer the rest.
  • Use a CDN and good cache headers so bytes arrive fast.
  • Preconnect to critical third-party origins.

Fixing CLS

Beginner Layout shift happens when content loads after paint and pushes things around. The fix is always "reserve the space up front":

<!-- Always set width/height (or aspect-ratio) on images & embeds -->
<img src="x.jpg" width="800" height="600" alt="…">        <!-- reserves the box -->
.media { aspect-ratio: 16 / 9; }                           <!-- for responsive -->
/* Reserve space for content injected by JS, so it can't shift the page */
.progress-bar { min-height: 34px; }
/* Load fonts without a reflow: swap with a matched fallback metric */
@font-face { font-family: Inter; src: url(inter.woff2); font-display: swap; size-adjust: 100%; }
Common CLS causes: images without dimensions, ads/embeds injected after load, web fonts swapping to a differently-sized face, and content inserted above what the user is reading (a late banner). This tutorial itself had a 0.163 CLS from its hero heading + a JS-populated progress bar settling after paint — fixed by reserving explicit heights. Reserve space; never insert above the fold after load.

Fixing INP

Intermediate INP is dominated by long JavaScript tasks blocking the main thread when the user interacts.

// Break up long work so the UI stays responsive
async function processAll(items) {
  for (const batch of chunk(items, 50)) {
    doWork(batch);
    await new Promise(r => setTimeout(r)); // yield to the main thread
  }
}
// Or offload heavy compute to a Web Worker entirely:
const worker = new Worker("/heavy.js");
worker.postMessage(data);
  • Debounce/throttle high-frequency handlers (input, scroll, resize).
  • Ship less JavaScript; code-split and lazy-load non-critical bundles.
  • Avoid synchronous layout thrashing (read then write DOM in batches).

Measuring

// Field data in your own app (real users, not a lab)
import { onLCP, onCLS, onINP } from "web-vitals";
onLCP(console.log); onCLS(console.log); onINP(console.log);
// Lab data: Chrome DevTools → Lighthouse, or `npx lighthouse <url>`
Lab (Lighthouse) and field (CrUX / web-vitals) data differ — the lab is a clean, controlled run; the field is messy real devices and networks. Optimize with the lab for fast iteration, but trust the field for whether users are actually having a good time.

Exercises

  • Run Lighthouse on a page you own; identify the LCP element and whether CLS or INP is weakest.
  • Add width/height to every image on a page and re-measure CLS.
  • Add the web-vitals library and log real LCP/CLS/INP from your own browsing.

Mini-project: get a page to all-green vitals

Take a slow/janky page and drive all three vitals into the "good" range: preload + right-size the LCP image, reserve dimensions on every image and JS-injected block to kill CLS, and break up or defer the heaviest script to cut INP. Verify with Lighthouse before/after and capture the score jump — exactly the LCP/CLS/INP tuning that took this tutorial's dashboard from Performance 93 to 99.
