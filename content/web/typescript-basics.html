TypeScript is JavaScript with a static type layer that's erased at build time. It catches bugs before you run the code and makes editors far smarter. Learn types, interfaces, unions and narrowing, generics, and the compiler settings that matter.

Types and inference

let count: number = 0;
let name = "Ada";          // inferred as string — annotation unnecessary
const ids: number[] = [1, 2, 3];
let pair: [string, number] = ["a", 1];   // tuple

function greet(who: string): string {
  return `Hi ${who}`;
}

// Let inference work; annotate function params and public APIs.
Annotate function parameters and return types of exported functions; let TypeScript infer local variables. Over-annotating locals is noise — the compiler already knows.

Interfaces and type aliases

interface User {
  id: number;
  name: string;
  email?: string;          // optional
  readonly createdAt: Date; // can't reassign after construction
}

type Point = { x: number; y: number };   // alias — equivalent for objects

const u: User = { id: 1, name: "Ada", createdAt: new Date() };

Rule of thumb: interface for object/class shapes (it can be extended and merged); type for unions, tuples, and function types.

Unions and narrowing

Intermediate A union says "one of these"; narrowing is how you safely access the specific one:

type Status = "idle" | "loading" | "error";   // literal union

function render(s: Status) {
  if (s === "error") { /* ... */ }   // narrowed to "error" here
}

function area(shape: { kind: "circle"; r: number } | { kind: "rect"; w: number; h: number }) {
  switch (shape.kind) {              // discriminated union
    case "circle": return Math.PI * shape.r ** 2;
    case "rect":   return shape.w * shape.h;
  }
}

// Narrowing with typeof / in / instanceof
function len(x: string | string[]) {
  return typeof x === "string" ? x.length : x.length;
}
Common mistake: reaching for any or the as cast to silence an error. any turns off type-checking for that value and infects everything it touches; as lies to the compiler. Prefer unknown + narrowing, or fix the underlying type. Reserve as for genuinely external, untyped data.

Generics

function first<T>(arr: T[]): T | undefined {
  return arr[0];
}
first([1, 2, 3]);        // T = number → number | undefined
first(["a", "b"]);       // T = string

interface ApiResponse<T> {
  data: T;
  error: string | null;
}
const res: ApiResponse<User[]> = { data: [], error: null };

// Constraints
function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;
}

Compiler configuration

// tsconfig.json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,            // ← the single most important flag
    "noUncheckedIndexedAccess": true,
    "skipLibCheck": true
  }
}
tsc --noEmit        # type-check only (bundlers/Bun do the transpiling)
Turn on "strict": true from day one. Adding it to an existing codebase later surfaces hundreds of errors at once; starting strict means you never accumulate the debt.

Exercises

  • Model a Result<T> discriminated union ({ok:true,value:T} | {ok:false,error:string}) and narrow it.
  • Write a generic groupBy<T>(items: T[], key: (t:T)=>string): Record<string, T[]>.
  • Take a function that uses any, replace it with unknown + narrowing, and watch the errors it now catches.

Mini-project: a typed API client

Build a typed fetch wrapper: api<T>(path: string): Promise<Result<T>> returning a discriminated union instead of throwing. Define User and Todo interfaces, call api<User[]>("/users"), and let the compiler enforce that you handle both the success and error branches. Run tsc --noEmit --strict clean.
