A Progressive Web App is an ordinary website that, with three additions — a manifest, a service worker, and HTTPS — becomes installable, works offline, and behaves like a native app. This very tutorial is a PWA; its source is the running example throughout this section.

What makes a site a PWA

Beginner Three installability requirements the browser checks:

  1. A web app manifest with a name, icons (192 & 512px), start_url, and a display mode.
  2. A registered service worker with a fetch handler (so it can work offline).
  3. Served over HTTPS (or localhost for development).

Meet those and browsers offer an "Install" option; the app then launches in its own window, with an icon, no browser chrome, and offline capability.

Project anatomy

/
├── index.html              ← app shell
├── app.css, app.js         ← static assets
├── manifest.webmanifest    ← install metadata
├── sw.js                   ← service worker (MUST be at the scope root)
├── offline.html            ← fallback when a page isn't cached
└── icon-192.png, icon-512.png, icon.svg
Scope matters: a service worker can only control pages at or below its own URL path. Put sw.js at the site root (/sw.js) so it controls everything. A worker at /js/sw.js only controls /js/* — a common "why isn't offline working" bug.

Linking the manifest

<!-- in <head> of every page -->
<link rel="manifest" href="/manifest.webmanifest">
<meta name="theme-color" content="#0d1117">
<link rel="icon" href="/icon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/icon-192.png">

Registering the service worker

if ("serviceWorker" in navigator) {
  window.addEventListener("load", () => {
    navigator.serviceWorker.register("/sw.js")
      .then((reg) => console.log("SW scope:", reg.scope))
      .catch((err) => console.error("SW failed:", err));
  });
}

The install prompt

Intermediate Browsers fire beforeinstallprompt when the criteria are met. Capture it to show your own install button instead of relying on the browser's menu:

let deferred = null;
const btn = document.querySelector("#install");

window.addEventListener("beforeinstallprompt", (e) => {
  e.preventDefault();          // stop the mini-infobar
  deferred = e;
  btn.hidden = false;          // reveal YOUR install button
});

btn.addEventListener("click", async () => {
  deferred.prompt();
  await deferred.userChoice;   // {outcome: "accepted" | "dismissed"}
  deferred = null;
  btn.hidden = true;
});

window.addEventListener("appinstalled", () => { btn.hidden = true; });
iOS Safari doesn't fire beforeinstallprompt; users install via Share → "Add to Home Screen". Detect standalone mode with window.matchMedia("(display-mode: standalone)").matches to tailor the UI once installed.

Auditing with Lighthouse

# Chrome DevTools → Lighthouse → "Progressive Web App" category
# or CLI:
npx lighthouse https://your-site --only-categories=pwa --view

Lighthouse checks installability, offline start, correct manifest, HTTPS, and viewport. Aim to clear every PWA item; the a11y/perf/best-practices categories are worth running too.

Exercises

  • Add a manifest + a trivial service worker to a plain HTML page and confirm Chrome shows "Install".
  • Wire a custom install button via beforeinstallprompt and hide it after appinstalled.
  • Run a Lighthouse PWA audit and resolve every failing item.

Mini-project: make an existing page installable

Take any static page you have, add manifest.webmanifest (name, icons, start_url, display: standalone), register a service worker that at minimum pre-caches the shell, serve it over HTTPS (or localhost), and get a green Lighthouse PWA audit.
