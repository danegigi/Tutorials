JavaScript is the behavior layer of the web and the only language browsers run natively. Learn values and functions, the single-threaded event loop, promises and async/await, ES modules, and manipulating the DOM.

Values, variables, and types

let count = 0;          // reassignable, block-scoped
const name = "Ada";     // not reassignable (use by default)
// avoid var — it's function-scoped and hoists confusingly

// 7 primitives + objects
typeof 42;        // "number"
typeof "hi";      // "string"
typeof true;      // "boolean"
typeof undefined; // "undefined"
typeof null;      // "object"  ← famous historical bug
typeof {};        // "object"
typeof [];        // "object"  — use Array.isArray([]) instead
Equality: use === (strict), never == (coercing). 0 == "" and null == undefined are true under ==, which causes subtle bugs. === compares type and value with no surprises.

Functions and closures

function add(a, b) { return a + b; }
const addArrow = (a, b) => a + b;      // arrow: concise, inherits `this`

// Closures capture their surrounding scope
function counter() {
  let n = 0;
  return () => ++n;
}
const next = counter();
next(); next();   // 1, 2

// Destructuring + defaults + rest
const greet = ({ name = "friend", ...rest }) => `Hi ${name}`;

Arrays and objects

const nums = [1, 2, 3, 4];
nums.map(n => n * 2);              // [2,4,6,8]
nums.filter(n => n % 2 === 0);    // [2,4]
nums.reduce((a, n) => a + n, 0);  // 10
nums.find(n => n > 2);            // 3

const user = { id: 1, name: "Ada" };
const { name } = user;             // destructure
const copy = { ...user, name: "Bo" };  // spread + override
Object.entries(user).forEach(([k, v]) => console.log(k, v));

The event loop

Intermediate JavaScript runs on a single thread. Long synchronous work freezes the UI. Asynchronous work (timers, network, events) is queued and processed when the call stack is empty:

console.log("1");
setTimeout(() => console.log("3 (macrotask)"), 0);
Promise.resolve().then(() => console.log("2 (microtask)"));
console.log("sync");
// Order: 1, sync, 2, 3  — microtasks (promises) drain before the next macrotask

Promises and async/await

// A promise represents a future value
async function loadUser(id) {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}

try {
  const user = await loadUser(1);
  console.log(user.name);
} catch (err) {
  console.error("failed:", err.message);
}

// Run independent requests concurrently
const [a, b] = await Promise.all([loadUser(1), loadUser(2)]);
Common mistakes: (1) forgetting await, so you work with a pending Promise instead of its value. (2) awaiting in a loop when the calls are independent — use Promise.all to parallelize. (3) not checking res.ok — fetch only rejects on network failure, not on a 404/500.

ES modules

export function add(a, b) { return a + b; }
export const PI = 3.14159;
export default function main() {}

// app.js
import main, { add, PI } from "./math.js";
<script type="module" src="app.js"></script>   <!-- in HTML -->

The DOM

const btn = document.querySelector("#save");
btn.addEventListener("click", (e) => {
  e.preventDefault();
  document.querySelector("#status").textContent = "Saved!";
});

// Create + insert
const li = document.createElement("li");
li.textContent = "New item";
document.querySelector("ul").append(li);

// Event delegation — one listener for many children
list.addEventListener("click", (e) => {
  const row = e.target.closest("li");
  if (row) remove(row.dataset.id);
});
Prefer textContent over innerHTML when inserting user data — innerHTML with untrusted strings is an XSS hole. Use event delegation for dynamic lists instead of attaching a listener per item.

Exercises
