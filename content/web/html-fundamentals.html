HTML is the structure layer of the web. Write it semantically — elements chosen for meaning, not appearance — and you get accessibility, SEO, and maintainability almost for free.

Document skeleton

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Page title</title>
  <meta name="description" content="One-sentence summary for search results.">
</head>
<body>
  <!-- content -->
</body>
</html>
Three non-negotiables: the <!DOCTYPE html> (triggers standards mode), lang on <html> (screen readers and translation), and the viewport <meta> (without it, mobile browsers render at desktop width and zoom out). Omitting any is a common, visible bug.

Semantic structure

Beginner Use landmark elements instead of a sea of <div>s. They give the page an outline that assistive tech and browsers understand:

<header>…site header, logo, nav…</header>
<nav>…primary navigation…</nav>
<main>
  <article>
    <h1>One h1 per page</h1>
    <section>
      <h2>A subsection</h2>
      <p>Paragraph text.</p>
    </section>
  </article>
  <aside>…related links…</aside>
</main>
<footer>…copyright, secondary links…</footer>
Heading levels (h1–h6) convey a document outline — never skip a level for visual size. Style a heading with CSS; don't pick <h4> because it "looks right".

Links and media

<a href="/about">About</a>
<a href="https://example.com" target="_blank" rel="noopener">External ↗</a>

<img src="/cat.jpg" alt="A tabby cat asleep on a keyboard" width="640" height="480">
<picture>
  <source srcset="/hero.avif" type="image/avif">
  <source srcset="/hero.webp" type="image/webp">
  <img src="/hero.jpg" alt="Mountain at sunrise">
</picture>
Common mistakes: (1) empty or missing alt on meaningful images — screen-reader users get nothing. (Decorative images get alt="" deliberately.) (2) Omitting width/height, which causes layout shift as images load. (3) target="_blank" without rel="noopener", a minor security/perf footgun.

Forms

<form action="/signup" method="post">
  <label for="email">Email</label>
  <input id="email" name="email" type="email" required autocomplete="email">

  <label for="pw">Password</label>
  <input id="pw" name="password" type="password" minlength="8" required>

  <button type="submit">Create account</button>
</form>

Every input needs a <label> tied by for/id — it's a clickable target and the accessible name. The type drives mobile keyboards and built-in validation (covered in Forms & Validation).

Tables (for tabular data only)

<table>
  <caption>Q3 revenue by region</caption>
  <thead><tr><th scope="col">Region</th><th scope="col">Revenue</th></tr></thead>
  <tbody><tr><th scope="row">EU</th><td>$1.2M</td></tr></tbody>
</table>
Don't use tables for page layout — that's what CSS Grid/Flexbox are for. Tables are for data; scope on headers makes them navigable by screen readers.

Exercises

  • Mark up a blog post using header/main/article/section/footer with a single h1 and a correct heading outline.
  • Add a responsive <picture> that serves AVIF/WebP with a JPEG fallback and proper alt.
  • Run the page through the browser's accessibility tree view and confirm the landmarks appear.

Mini-project: a semantic resume page
