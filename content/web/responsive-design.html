Responsive design means one layout that adapts from a 360px phone to a 4K monitor. The tools: the viewport meta tag, fluid units, media and container queries, and responsive images. Build mobile-first and let layouts grow.

The viewport (prerequisite)

<meta name="viewport" content="width=device-width, initial-scale=1">
Without this tag, mobile browsers assume a ~980px desktop canvas and shrink the page to fit — your careful mobile layout never activates. It's the single most common reason "my responsive CSS isn't working on my phone".

Fluid units

UnitRelative toUse for
%Parent sizeWidths within a container
remRoot font sizeSpacing, type (scales with user prefs)
vw/vhViewportFull-bleed sections, hero heights
chCharacter widthReadable line length (max-width: 65ch)
clamp()min, preferred, maxFluid type/spacing without breakpoints
 
/* Fluid type: never below 1rem, never above 2rem, scales with viewport */
h1 { font-size: clamp(1.5rem, 1rem + 2.5vw, 2.5rem); }

/* Readable measure */
article { max-width: 65ch; margin-inline: auto; }

Mobile-first media queries

Beginner Write the small-screen styles as the base, then layer enhancements with min-width queries. This keeps the base simple and avoids overriding desktop styles down to mobile.

/* Base: mobile — single column */
.grid { display: grid; gap: 16px; }

/* Tablet and up */
@media (min-width: 48rem) {
  .grid { grid-template-columns: 1fr 1fr; }
}
/* Desktop and up */
@media (min-width: 72rem) {
  .grid { grid-template-columns: repeat(3, 1fr); }
}
Pick breakpoints where the content breaks, not at specific device widths — chasing "iPhone 15 is 393px" is a losing game. Resize the browser slowly and add a breakpoint when the layout starts to look wrong.

Container queries

Intermediate Media queries react to the viewport; container queries react to a component's own width — so a card adapts whether it's in a wide main area or a narrow sidebar:

.card-list { container-type: inline-size; }

/* When the CONTAINER is ≥400px, not the viewport */
@container (min-width: 400px) {
  .card { display: grid; grid-template-columns: 120px 1fr; }
}

Responsive layout without queries

/* Auto-fitting grid: as many columns as fit, each ≥240px */
.gallery {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: 16px;
}
/* Flex wrap: items flow to new rows when they run out of room */
.tags { display: flex; flex-wrap: wrap; gap: 8px; }

Responsive images

<img src="small.jpg"
     srcset="small.jpg 480w, medium.jpg 960w, large.jpg 1600w"
     sizes="(min-width: 72rem) 50vw, 100vw"
     alt="…" width="1600" height="900">

The browser picks the smallest adequate file for the device's screen and the slot's rendered width — saving bandwidth on phones. Always include intrinsic width/height to reserve space and prevent layout shift.

Respecting user preferences

@media (prefers-color-scheme: dark) { :root { --bg: #0d1117; } }
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}

Exercises

  • Make a heading fluid with clamp() and confirm it scales smoothly with no breakpoints.
  • Build a 1→2→3 column grid, mobile-first, with min-width queries at content-driven breakpoints.
  • Add a srcset/sizes image and watch the network panel load different files as you resize.

Mini-project: a responsive product page

Build a product page that is a single column on mobile, image-beside-details on tablet, and adds a related-items rail on desktop — using one auto-fit grid plus two breakpoints. Make a card component adapt via a container query so it works in both the main column and a sidebar, honor prefers-reduced-motion, and verify at 360/768/1440px.
